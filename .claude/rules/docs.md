# Документация

Полная политика — `docs/dev/documentation.md`; что обновлять при каком изменении — её §3.

- README — до 90 строк; подробности — ссылкой в `docs/`.
- Один факт — одно место: версии и совместимость — `docs/compatibility.md`; состояние работ —
  `docs/roadmap.md`; пути и права — `docs/architecture/data-model.md`; команды —
  `docs/architecture/interfaces.md`.
- `docs/architecture/` описывает, как устроено; «почему» — в ADR. Принятый ADR не
  переписывается: новое решение — новый ADR (скил `adr`).
- Датированный факт — с датой, источником и способом проверки; непроверенное так и называется.
- В примерах только фиктивные значения из `docs/security/secrets.md` §4.
- Не обещать обход DPI и блокировок; диагностика «измеряет», а не «определяет блокировку».
- Таблица вместо перечисления свойств; схема — Mermaid; документ длиннее 100 строк начинается
  с содержания; ссылки — относительные.
- Термины — по `docs/README.md` §2; новый термин добавляется туда.
- После правки — `bash scripts/check.sh` (ссылки, пути, пределы, статусы ADR).
