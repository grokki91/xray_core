# Правка инструкций

Устройство экосистемы и её таблицы — `docs/dev/ai-ecosystem.md`.

- **Что где.** `AGENTS.md` — только верное в каждой сессии; процедуры туда не пишутся.
  `CLAUDE.md` — `@AGENTS.md` и особенности Claude Code. Правило — что делать при правке файлов
  из `paths` (во фронтматтере только `paths`). Скил — процедура по типу задачи. Субагент —
  работа в отдельном контексте с фиксированной формой ответа. Хук — автоматическая проверка.
- **Пределы строк**: `AGENTS.md` 150, `CLAUDE.md` 40, правило 40, `SKILL.md` 150 (подробности —
  в `references/`, ссылки на них только из `SKILL.md`), субагент 60.
- **Один факт — одно место.** Политика живёт в `docs/`; правило и скил дают выжимку «что
  делать» и ссылку, а не пересказ. Двух правил, противоречащих друг другу, быть не должно.
- **Без изменчивого.** Даты, версии, состояние фаз — в `docs/compatibility.md` и
  `docs/roadmap.md`, не в инструкциях: стабильный префикс кешируется.
- **Каждая строка стоит контекста.** Писать, что делать и почему; общеизвестное не пересказывать.
- **Скил**: `name` равен имени каталога; `description` до 1024 символов — что делает и когда
  применять, словами владельца.
- **Новый элемент** — только при повторяющейся потребности; вместе с ним строка в таблице
  `docs/dev/ai-ecosystem.md` §3.
- **Хук**: меняется поведение — сценарий в `tests/test-guards.sh`; новый хук — запись в
  `.claude/settings.json`. Блокирующий хук без `jq` отказывает, а не пропускает.
- Данных установки нет и в инструкциях (`docs/security/secrets.md` §4).
- После правки — `bash scripts/check.sh`.
