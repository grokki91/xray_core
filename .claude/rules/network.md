# Сеть, DNS и узел

Политика — `docs/security/policy.md` §4 и §7; здесь — что из неё следует при правке этих пакетов.

- Доступ владельца по SSH важнее любой функции: правило фаервола, маршрут, sysctl, настройка SSH
  и системный резолвер не меняются, пока ADR не назвал, кто меняет, как это откатывается и чем
  после изменения проверяется, что SSH по-прежнему отвечает.
- Изменение сети — только внутри транзакции `app`; возврат прежнего значения — часть отката, и
  на него есть тест «сбой после изменения → прежнее значение».
- `network` и `dns` только читают; исключение одно — правило UFW для порта Xray
  (`AllowPort`, `RevokePort`, [ADR-0041](../../docs/adr/0041-ufw-rule-in-install-transaction.md)):
  его вызывает только транзакция `app`. Остальное, что меняет систему, живёт у менеджера,
  названного ADR.
- Сетевой факт — не вывод: «порт слушается» не значит «доступен извне», исходящая связность не
  доказывает входящую. Чего с сервера не измерить — «не определено», а не предположение.
- Внешний адрес для проверки — только из закрытого списка с строкой в `docs/dev/dependencies.md`
  §5; адрес сервера третьей стороне не раскрывается сверх этого списка.
- Проверка чужого узла (цель REALITY, контрольный узел) — одно соединение, без перебора адресов
  и портов: измерение не должно выглядеть сканированием.
- У каждого сетевого вызова — срок из контекста; IPv4 и IPv6 проверяются и сообщаются раздельно.
- Различия версий ОС и утилит — в `platform`, не здесь.
- Изменение этих пакетов — повод для субагента `security-reviewer`.
