# Диагностика

Полное описание — `docs/operations/diagnostics.md`. Диагностика измеряет наблюдаемое и
называет пределы измерения; она не объявляет блокировку.

## Модель в одну строку

Проверка → наблюдения (что, откуда, значение, `limits`) → правила анализа → выводы с классом.

| Класс | Когда |
|---|---|
| `fact` | прямо следует из наблюдений этой точки |
| `probable` | два и более независимых наблюдения; названы альтернативные объяснения |
| `hypothesis` | из доступных точек не проверяется; названо, что подтвердит и что опровергнет |

Нельзя ослабить: таймаут — только наблюдение; вывод о фильтрации никогда не `fact`; с одной
локальной точкой — не выше `hypothesis`; `probable` — только при здоровом сервере и расхождении
внешних точек в одном окне времени.

## Как добавить проверку

1. Идентификатор `<категория>.<предмет>[.<свойство>]`; категория — из каталога §4 документа.
2. Что именно измеряется и чем; чего измерение не различает — это `limits`, без него проверка
   не принимается.
3. Состояния: `ok`, `fail`, `skip` (с причиной: нет адреса, нет утилиты, нужна внешняя точка),
   `error` (сама проверка сломалась).
4. Правило анализа: из каких наблюдений какой вывод и какого класса. Вывод класса `probable`
   обязан перечислять альтернативы.
5. Тесты: по сценарию на каждое состояние; для правила — что класс не завышается.
6. Бюджет: время и соединения в пределах §5 документа; тяжёлая проверка — только по явному выбору.
7. Строка в каталоге `docs/operations/diagnostics.md` §4; новое поле отчёта — по правилам
   контракта (`docs/architecture/interfaces.md` §2).

## Как разбирать отчёт владельца

1. Работать только с отредактированным экспортом (`xm diag --export`); сырой вывод с сервера
   не просить и не сохранять.
2. Сначала факты, затем вероятные причины, затем гипотезы — в ответе они тоже раздельно.
3. К каждой гипотезе — что её проверит: команда, клиент из другой сети, внешняя точка.
4. Не хватает данных — один список: что нужно, зачем и какой командой получить.
5. Обобщаемый вывод разбора — новая проверка или правило, а не абзац в ответе.

## Ловушки

- «Не отвечает» с сервера и «не отвечает» у клиента — разные наблюдения разных точек.
- Исходящая связность сервера не доказывает входящую, и наоборот.
- Расхождение ответов DNS бывает законным (CDN): это наблюдение, а не вывод о подмене.
- Измерение не должно само выглядеть аномалией: без серий одновременных соединений к одному узлу.
- Журнал Xray показывает симптом (отклонённое рукопожатие), а не причину.
