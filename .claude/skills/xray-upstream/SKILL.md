# Факты об upstream

Xray меняется между выпусками: значения по умолчанию, правила рукопожатия, имена полей. Память
модели и статьи устаревают; код опирается только на проверенное и записанное.

## Где правда — по убыванию веса

1. Исходный код и коммиты по тегу: `XTLS/Xray-core`, `XTLS/REALITY`, документация
   `XTLS/Xray-docs-next`; для клиентов — их репозитории и репозитории их ядер.
2. Поведение бинарника: `xray run -test` на конфигурации, `xray version`, сквозной тест.
3. Замеры с данными (обращения в трекерах с журналами).
4. Обзоры и статьи — повод проверить, не факт.

## Порядок

1. Найти строку в `docs/compatibility.md`. Есть и моложе трёх месяцев — использовать.
2. Нет или устарела — проверить по источнику уровня 1–2. Чтение чужих исходников поручать
   субагенту `upstream-researcher`: в основной контекст возвращается только факт.
3. Записать в `docs/compatibility.md`: дата, факт, источник (файл и тег или коммит), способ
   проверки — «по исходникам», «на бинарнике», «на устройстве», «по пересказу».
4. Код, опирающийся на факт, правится в той же правке; порог или версия — константа с ссылкой на
   строку таблицы, а не число в середине функции.
5. Снятый факт переносится в раздел «Устарело» с датой и причиной.

## Что проверять всегда

- Поле конфигурации существует в версиях проверенного диапазона и называется так же.
- Значение по умолчанию не изменилось между границами диапазона.
- Отрисованная конфигурация проходит `xray run -test` на обеих границах.
- Правило рукопожатия REALITY и требования к ClientHello — по коду `XTLS/REALITY` той ревизии,
  что указана в `go.mod` тега Xray.
- Формат файлов релиза и сумм — по самому релизу (`docs/operations/updates.md` §3).

## Расширение проверенного диапазона

1. Новая версия проходит уровни L3 и L4 (`docs/testing.md`).
2. Просмотреть изменения между тегами в частях, которые использует проект: REALITY, транспорт
   пресета, DNS, маршрутизация, API статистики, подкоманды.
3. Обновить таблицу клиентов: кто перестал или начал подключаться.
4. Изменение диапазона и таблицы — одной правкой.

## Ловушки

- «Latest» на GitHub и последний тег — не одно и то же: стабильность выпуска проверяется.
- Сайты и API могут быть недоступны из песочницы; публичные репозитории клонируются напрямую.
  Что проверить не удалось — так и записать, не заменять пересказом.
- Контроль после обновления использует клиент на том же ядре и не доказывает совместимость
  сторонних ядер.
- Формулировки про обход блокировок из чужих источников в документы проекта не переносятся.
