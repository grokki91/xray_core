# Клиентские профили и артефакты

Артефакт строится в одном месте — экспортёром в `profile/export`. CLI, панель и мост получают
готовый результат и сами ссылок не собирают.

## Правила

- Один формат — один экспортёр; общие части (кодирование имени, адрес IPv6 в квадратных
  скобках, порядок параметров) — общие функции пакета.
- Вход экспортёра — профиль, адрес сервера и параметры пресета; выход — артефакт или ошибка.
  Состояние экспортёр не читает и не меняет.
- Пара «клиент × пресет», которой нет в таблице совместимости как рабочей, — ошибка с причиной
  и минимальной версией клиента. «Приблизительных» ссылок нет.
- Ссылка и QR — секрет класса S1 (`docs/security/secrets.md` §1): только на экран по команде
  владельца; в журнал, отчёт и тестовые файлы не попадают.
- QR кодирует ровно ту же строку, что показана ссылкой.

## Ссылка VLESS

Общий вид: `vless://<uuid>@<адрес>:<порт>?<параметры>#<имя>`.

| Параметр | Значение | Когда |
|---|---|---|
| `encryption` | `none` | всегда |
| `security` | `reality` | пресеты REALITY |
| `sni` | имя из `server_names` | REALITY |
| `fp` | отпечаток TLS-клиента | REALITY |
| `pbk` | публичный ключ | REALITY |
| `sid` | shortId | REALITY |
| `type` | `tcp` или `xhttp` | транспорт пресета |
| `flow` | `xtls-rprx-vision` | только Vision поверх TCP |
| `path`, `mode` | путь и режим | только XHTTP |

Таблица — ожидаемый набор; по исходникам клиентов он не сверялся. До реализации экспортёра
сверить разбор ссылок в v2rayN и Hiddify (субагент `upstream-researcher`) и записать результат
в `docs/compatibility.md`. Значение `fp` и порядок параметров — по той же сверке.

## Как добавить формат или клиента

1. Строка в таблице клиентов `docs/compatibility.md` §3 с датой и источником; с фазы 3 —
   та же строка в данных `profile/compat`.
2. Экспортёр с тестами: эталон на фиктивных данных; обратный разбор даёт те же параметры;
   адрес IPv4, IPv6 и домен; имя с недопустимыми символами отвергается раньше.
3. Сквозной тест, где это возможно: клиентское ядро принимает артефакт и проходит через петлю
   (`docs/testing.md`, уровень L3).
4. «Проверено на устройстве» в таблицу вносит только владелец после ручной проверки.

## Ловушки

- IPv6 без квадратных скобок ломает разбор у всех клиентов.
- Один артефакт — один адрес: выбор «IPv6, затем IPv4» делает клиент, не ссылка.
- Клиенты на форках sing-box и на upstream sing-box ведут себя по-разному: строка таблицы — на
  конкретный клиент и версию, а не на «ядро sing-box».
- В примерах — только фиктивный UUID и заглушка ключа: иначе запись остановит хук.
