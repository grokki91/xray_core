# Данные на VPS

Что `xm` хранит, где, с какими правами и сколько. В репозитории этих данных нет: только шаблоны и
примеры с фиктивными значениями ([secrets.md](../security/secrets.md) §4).

## 1. Раскладка и манифест прав

Одна таблица — источник для `security.EnsureBaseline` (привести) и `security.Audit` (сверить).

| Путь | Владелец | Права | Секреты | Назначение |
|---|---|---|---|---|
| `/usr/local/bin/xm` | root:root | 0755 | нет | менеджер |
| `/usr/local/lib/xm/core/<версия>/xray` | root:root | 0755 | нет | бинарники Xray (две версии) |
| `/usr/local/lib/xm/core/current` | root:root | ссылка | нет | активная версия |
| `/etc/xm/` | root:root | 0700 | да | каталог состояния |
| `/etc/xm/state.json` | root:root | 0600 | да | источник правды |
| `/usr/local/etc/xray/` | root:xray | 0750 | да | каталог конфигурации Xray |
| `/usr/local/etc/xray/config.json` | root:xray | 0640 | да | производный артефакт |
| `/etc/systemd/system/xray.service` | root:root | 0644 | нет | юнит с меткой `xm` |
| `/var/lib/xm/` | root:root | 0700 | да | данные менеджера |
| `/var/lib/xm/backups/` | root:root | 0700, файлы 0600 | да | снимки |
| `/var/lib/xm/tx/` | root:root | 0700 | да | журнал незавершённой транзакции |
| `/var/lib/xm/diag/` | root:root | 0700, файлы 0600 | нет (отредактировано) | история диагностики |
| `/var/lib/xm/monitor/` | root:root | 0700, файлы 0600 | нет | хронология замеров |
| `/var/lib/xm/cache/` | root:root | 0700 | нет | загруженные архивы релизов |
| `/run/xm/` | root:root | 0700 | да | блокировка, сессия `xm ui` |

Журналы — journald (`xray.service` и идентификатор `xm`), собственных файлов журналов нет.

## 2. Состояние `state.json`

Единственный файл, который описывает установку. Пишется атомарно и только внутри транзакции.
Пример с фиктивными данными:

```json
{
  "schema_version": 1,
  "server": {
    "addresses": {"ipv4": "203.0.113.10", "ipv6": "2001:db8::10", "domain": ""},
    "port": 443
  },
  "inbounds": [
    {
      "preset": "reality-xhttp",
      "reality": {
        "target": "example.com:443",
        "server_names": ["example.com"],
        "private_key": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
        "public_key": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
        "short_ids": ["0123456789abcdef"]
      },
      "params": {"path": "/example"}
    }
  ],
  "profiles": [
    {"name": "phone", "id": "00000000-0000-4000-8000-000000000001", "created": "2026-01-01T00:00:00Z", "enabled": true}
  ],
  "dns": {"doh": ["https://1.1.1.1/dns-query"], "strategy": "UseIP"},
  "core": {"version": "26.11.9", "previous": "26.10.21", "hold": false},
  "applied": {"config_sha256": "<sha256 последнего применённого config.json>", "at": "2026-01-01T00:00:00Z"}
}
```

- `schema_version` меняется только вместе с миграцией в `store`; миграция выполняется внутри
  транзакции и покрыта тестом «старый файл → новый файл».
- `inbounds` — список, в MVP ровно один элемент: второй пресет добавляется без миграции.
- Профиль — пользователь сервера: присутствует во всех входящих; экспорт даёт по артефакту на
  каждую пару «входящий × адрес».
- Формат — JSON: разбирается стандартной библиотекой, руками не правится.

## 3. Конфигурация Xray

`/usr/local/etc/xray/config.json` получается из состояния функцией `config.Render` и содержит
секреты (приватный ключ REALITY, идентификаторы клиентов), поэтому читается только root и
пользователем службы. Сравнение SHA-256 файла с `applied.config_sha256` выявляет ручную правку
(дрейф).

## 4. Снимки

`/var/lib/xm/backups/<UTC-время>-<причина>.tar.gz`: `state.json`, `config.json`, `manifest.json`
(версии `xm` и Xray, версия схемы, SHA-256 каждого файла).

| Вид | Когда создаётся | Хранится |
|---|---|---|
| автоматический | перед каждой транзакцией | 10 последних |
| ручной | `xm backup` | 20 последних |

Восстановление: проверить манифест → снимок текущего состояния → обычная транзакция с состоянием
из архива. Снимок не шифруется на диске (он не секретнее соседнего `state.json`); выгрузка за
пределы VPS — отдельное решение после MVP.

## 5. История диагностики и мониторинга

| Данные | Формат | Предел |
|---|---|---|
| отчёты `xm diag` | JSON на отчёт, уже отредактированный | 50 отчётов |
| замеры `monitor` | JSONL, файл на сутки | 14 суток |

Значения пределов — исходные, уточняются замером в фазе 6. Превышение предела удаляет самое
старое; общий объём `/var/lib/xm` входит в бюджет [overview.md](overview.md) §8.

## 6. Удаление

- `xm uninstall` снимает службу, юнит, бинарники Xray и `xm`; `/etc/xm` и `/var/lib/xm/backups`
  остаются — повторная установка поднимет прежние профили.
- `xm uninstall --purge` удаляет всё из таблицы §1 после подтверждения вводом слова.
- Файлы и каталоги вне таблицы §1 `xm` не удаляет никогда.
