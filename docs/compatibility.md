# Совместимость: ОС, версии Xray, клиенты

Здесь всё, что устаревает. У каждой строки — дата и источник. Строка старше трёх месяцев сначала
перепроверяется, потом используется. Порядок обновления — §4.

## 1. Операционные системы

| Уровень | ОС | Что это значит |
|---|---|---|
| Основной | Ubuntu Server 22.04, 24.04, x86_64 | системные тесты на каждом релизе; ошибки исправляются |
| Проверяемый | Ubuntu Server 26.04, x86_64 | совместимость проверяется перед релизом; расхождения фиксируются здесь |
| Унаследованный | Ubuntu Server 20.04, x86_64 | см. ниже; решение — вопрос Q8 |
| Вне поддержки | другие дистрибутивы, системы без systemd, другие архитектуры | `xm install` останавливается с объяснением |

Оценка Ubuntu 20.04: статический бинарник `xm` и upstream-бинарник Xray от версии ОС не зависят;
отличие — systemd 245 против 249 (22.04) и 255 (24.04): часть директив изоляции юнита он не
знает и пропускает с предупреждением, то есть служба работает с более слабой изоляцией.
Стандартная поддержка 20.04 закончилась в 2025 году. Предложение: ставить только с явным флагом
и предупреждением, без системных тестов и без обещаний.

Архитектура arm64 — кандидат на расширение: Go собирает под неё без изменений, upstream
публикует сборку Xray; нужна только строка в матрице тестов.

## 3. Клиенты

Сервер — Xray ≥ v26.9.9 с REALITY. «По исходникам» — вывод из кода клиента, на устройстве не
проверялось; «предшественник» — данные справочника `grokki91/xray` с его датой.

| Клиент | Ядро | Подключение по REALITY | XHTTP | Статус и источник |
|---|---|---|---|---|
| v2rayN (Windows, Linux, macOS) | Xray-core | да, при ядре не старше v25.7.26 и отпечатке `chrome` | да | предшественник, 2026-10-28; последний тег клиента 7.25.6 (2026-11-13) |
| v2rayNG (Android) | Xray-core | да, при том же условии | да | предшественник, 2026-10-28 |
| Hiddify 5.x | форк sing-box | да — по исходникам v5.2.0 и v5.5.5 | да | предшественник, 2026-11-06; последний тег v5.9.0 (2026-11-13) не перепроверялся |
| Hiddify 4.x | форк sing-box 1.13 | **нет**: вырезает X25519MLKEM768 из ClientHello | — | предшественник, 2026-10-28 |
| sing-box (upstream) 1.14.4 и 1.15.0-alpha.13 | sing-box | **нет**: REALITY-клиент вырезает X25519MLKEM768 | **нет** такого транспорта | по исходникам, 2026-11-13: `common/tls/reality_client.go`, каталог `transport/` |

Следствия для проекта:

- Требование совместимости с sing-box сегодня выполнимо только через Hiddify 5.x. Upstream
  sing-box к актуальному Xray по REALITY не подключается независимо от транспорта, и настройкой
  сервера это не исправить. Варианты — вопрос Q2.
- Среди целевых клиентов выбор между XHTTP и Vision совместимость не меняет: v2rayN и Hiddify 5.x
  умеют оба. Выбор пресета по умолчанию — вопрос Q1.
- Таблица — причина держать совместимость данными: экспорт профиля и `xm status` должны говорить
  «этот клиент этой версии не подключится» до того, как владелец увидит таймаут.

## 4. Как обновлять

1. Вес источников: исходный код и коммиты upstream и клиентов → замеры с данными → обзоры и
   статьи как повод проверить, но не как факт.
2. Каждой строке — дата проверки и источник; способ проверки называется («по исходникам», «на
   устройстве», «по пересказу»).
3. Публичные исходники клонируются и читаются напрямую — субагент `upstream-researcher`.
4. Снятая строка не удаляется, а переносится в раздел «Устарело» с датой и причиной.
5. С фазы 3 машинная копия таблицы клиентов живёт в `internal/profile/compat`; тест следит, что
   она и этот документ не расходятся. Код, который опирается на версию или порог, правится в
   одной правке с этой страницей.
