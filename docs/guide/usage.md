# Эксплуатация xm

Руководство владельца после установки ([install.md](install.md)): профили, обновление, снимки,
диагностика, журналы. Все флаги и коды выхода — [interfaces.md](../architecture/interfaces.md) §1;
пути и права — [data-model.md](../architecture/data-model.md) §1. Команды, кроме `version` и
`help`, выполняются от root.
Установка и удаление (`xm install`, `xm uninstall`) — [install.md](install.md); `xm version` —
версия `xm`, `xm help` и `xm <команда> -h` — справка.

|---|---|

| [2](#2-профили) | выдать, показать и отозвать доступ |
| [3](#3-обновление) | обновить Xray и сам `xm`, откатиться |
| [4](#4-снимки) | сохранить и восстановить состояние |

| [6](#6-коды-выхода) | понять итог команды |

## 1. Состояние и служба

```bash
sudo xm status
```

Служба, версии `xm` и Xray, адреса и порт, дрейф конфигурации, число профилей, доступное
обновление — по итогу последней проверки, без сети. Последняя строка — вердикт: состояние,
первопричина и действие. Вердикт `ok` значит «сервер готов принимать»; доступность извне с
сервера не проверяется.

`sudo xm stop`, `sudo xm start`, `sudo xm restart` — служба Xray. Остановленная служба остаётся
остановленной и после `xm add`, `xm update` и других изменений: запускают её только `xm start` и
`xm restart` ([ADR-0025](../adr/0025-stopped-service-and-install-scenario.md)).

## 2. Профили

Профиль — доступ одного устройства или человека. Ссылка и QR — секрет: передавайте их только по
защищённому каналу; `xm` не пишет их в журнал.

| Команда | Что делает |
|---|---|
| `sudo xm add phone` | новый профиль: ссылка на каждый адрес сервера и QR одной из них; без имени — `profile-N` |
| `sudo xm show phone` | те же ссылки и QR повторно |
| `sudo xm list` | имена, даты и состояние профилей без секретов |
| `sudo xm rm phone` | удалить профиль: его ссылка перестаёт подключаться |

С флагом `--client <id>` (список — [interfaces.md](../architecture/interfaces.md) §1) `xm` заранее
откажет, если этот клиент к серверу не подключится, и назовёт причину. Какие клиенты подходят и с
какими версиями — [compatibility.md](../compatibility.md) §3.

## 3. Обновление

| Команда | Что делает |
|---|---|
| `sudo xm update --check` | только узнать, есть ли новая версия Xray; ничего не меняет |
| `sudo xm update` | поставить последнюю стабильную версию Xray внутри проверенного диапазона |
| `sudo xm update --to <версия>` | поставить названную версию; вне проверенного диапазона — с предупреждением |
| `sudo xm update --rollback` | вернуть предыдущую версию Xray, без сети |
| `sudo xm update --self` | обновить сам `xm` до последнего выпуска |

Каждое обновление — транзакция с проверкой сумм, снимком и контролем после перезапуска. Не
прошёл контроль — служба возвращается на прежнюю версию, код 1. Профили и ключи не меняются;
`xm update --self` к тому же перерисовывает конфигурацию правилами нового `xm`, поэтому повторный
`install.sh` не нужен. Порядок шагов — [updates.md](../operations/updates.md) §4–§6.

## 4. Снимки

Перед каждым изменением `xm` сам сохраняет автоснимок; ручные снимки хранятся отдельно и
автоснимками не вытесняются. Сколько хранится — [data-model.md](../architecture/data-model.md) §4.

```bash
sudo xm backup
```

```bash
sudo xm backup --list
```

```bash
sudo xm restore <id>
```

`restore` спрашивает подтверждение — слово `restore` — и возвращает состояние из снимка
транзакцией: конфигурация перерисовывается, служба проверяется, текущее состояние уходит в
автоснимок. Версия Xray не меняется. Снимок содержит ключи: копируйте его с сервера только как секрет.

## 5. Диагностика и журналы

```bash
sudo xm diag
```

Проверяет с самого сервера Xray, порт и локальный фаервол, IPv4 и IPv6, ресурсы узла. Отчёт
разделяет факты, вероятные причины и гипотезы; проблемы — код 4. `--only <категория>` —
одна категория из [interfaces.md](../architecture/interfaces.md) §1. Вывод о фаерволе хостера или фильтрации в сети —
не больше чем гипотеза: проверить её можно только снаружи. Модель отчёта —
[diagnostics.md](../operations/diagnostics.md).

Показать отчёт кому-то, в том числе LLM, — только экспортом: в файле нет адресов, ключей и
идентификаторов.

```bash
sudo xm diag --export /root/diag.json
```

Журнал Xray и `xm` — отредактированный, по строке на запись:

```bash
sudo xm logs --since 1h
```

`-f` — следить до Ctrl-C; формат `--since` и пределы — [interfaces.md](../architecture/interfaces.md) §1.

## 6. Коды выхода

Смысл кодов — [interfaces.md](../architecture/interfaces.md) §1. Что делать владельцу:

| Код | Что делать |
|---|---|
| 1 | прочитать сообщение: в нём причина, что откатилось и следующий шаг |
| 2 | сверить аргументы: `xm <команда> -h` |
| 3 | исправить предусловие, названное в сообщении |
| 4 | `xm diag`: действие — в строке вердикта |
| 5 | выполнить шаги из сообщения точно по порядку |
