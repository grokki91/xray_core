# ADR-0013: Распространение `xm` и загрузчик

- Статус: Принято (инструменты выпуска — после согласия, Q5)
- Дата: 2026-11-13

## Контекст

Сценарий — одна команда из README на чистом VPS. Бинарник Go нужно доставить на сервер, где нет
ни Git, ни компилятора, и доставить так, чтобы подмену можно было заметить.

## Решение

- `xm` публикуется в релизах этого репозитория: бинарник для linux/amd64 и файл `SHA256SUMS`.
  Сборка воспроизводимая (`-trimpath`, без cgo, версия из тега).
- `install.sh` — минимальный загрузчик: проверить root и архитектуру, скачать бинарник и суммы,
  сверить SHA-256, положить в `/usr/local/bin/xm`, запустить `xm install`. Вся остальная логика —
  в `xm install`, где она тестируется.
- Тело `install.sh` — в функции, вызываемой последней строкой.
- README даёт три варианта: в одну строку; «скачать, прочитать, запустить»; с фиксированной версией.
- `xm update --self` использует тот же источник и ту же проверку.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| `git clone` и запуск скриптов (как у предшественника) | требует Git; код исполняется из рабочего каталога без проверки целостности |
| Сборка на VPS | тулчейн в сотни мегабайт и минуты процессора на 1 vCPU |
| Пакет `.deb` и свой репозиторий apt | инфраструктура подписи и размещения ради одного файла |
| Docker-образ | Docker не должен быть обязательным |

## Последствия

- Доверие к установке сводится к доверию GitHub и TLS; сумма рядом с бинарником защищает от
  порчи, а не от компрометации выпуска. Усиление — подтверждение происхождения сборки
  ([tooling.md](../dev/tooling.md)).
- Нужен конвейер выпуска; до согласия на CI выпуск невозможен — это первая задача фазы 1.
- `curl` должен быть на сервере: загрузчик его не ставит и сообщает, если его нет.
