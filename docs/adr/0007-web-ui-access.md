# ADR-0007: Web UI — петля, разовый токен, SSH-туннель

- Статус: Ждёт решения (Q6)
- Дата: 2026-11-13

## Контекст

Панель выполняет привилегированные действия. Её нельзя открывать в интернет; при этом на самом
VPS к петлевому адресу могут обратиться локальные процессы, а без специального правила — и
клиенты VPN через тоннель.

## Решение (рекомендация)

- `xm ui` слушает только `127.0.0.1:<порт>`; флага для публичного адреса нет.
- Доступ владельца — SSH-туннель (`ssh -L`).
- Вход — разовый токен во фрагменте ссылки, обмен на сессионную cookie
  (`HttpOnly`, `SameSite=Strict`); проверяются `Host` и `Origin`; изменяющие запросы требуют
  собственный заголовок.
- Процесс завершается после 30 минут без запросов.
- В конфигурации Xray адреса назначения из петлевых и частных сетей уходят в `blackhole` —
  обязательная часть любого пресета.
- Набор эндпоинтов закрытый: нет произвольных команд, путей и управления службой.

## Альтернативы

| Вариант | Почему нет (или когда да) |
|---|---|
| Сокет UNIX и `ssh -L порт:/путь` | сильнее изолирует от локальных процессов; не все SSH-клиенты умеют, сложнее в объяснении — запасной вариант, если владелец предпочтёт изоляцию удобству |
| Публичный HTTPS с паролем | прямо запрещено требованиями: постоянная поверхность атаки |
| Разделение привилегий (непривилегированный веб-процесс и привилегированный помощник) | сложность двух процессов; рассмотреть в фазе 8, если ревью безопасности потребует |

## Последствия

- Процесс панели работает от root, пока запущен: его защищают короткая жизнь, закрытый набор
  действий и проверка ввода.
- Правило `blackhole` для частных сетей становится проверяемым требованием безопасности:
  системный тест «через тоннель панель недостижима».
- Токен не попадает в журналы сервера и историю оболочки на VPS: он печатается в терминал и
  живёт во фрагменте ссылки.
