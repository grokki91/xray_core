# ADR-0005: Изменение системы — транзакция с откатом

- Статус: Принято
- Дата: 2026-11-13

## Контекст

Ошибка при изменении конфигурации или обновлении оставляет владельца без VPN, а иногда и без
понимания, в каком состоянии сервер. Требуются безопасное применение, резервные копии и
восстановление после ошибок.

## Решение

Любое действие, меняющее состояние, конфигурацию, версию ядра или службу, выполняется одним
каркасом в `app`:

1. блокировка;
2. снимок;
3. новое состояние и конфигурация во временных файлах;
4. проверка `xray run -test`;
5. атомарная запись;
6. перезапуск службы;
7. контроль: служба активна, порт слушается, самопроверка;
8. фиксация — или откат к снимку с повторным контролем.

- Запись о незавершённой транзакции лежит в `/var/lib/xm/tx/`; следующий запуск `xm` сначала
  откатывает её.
- Провал отката — отдельный код выхода 5 и точные инструкции; `xm` в этом случае больше ничего
  не меняет.
- Откат — обязательная часть операции, а не запасной путь: других «режимов на случай ошибки» нет.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Применять шаги по очереди и чинить вручную | половинчатое состояние после сбоя |
| Откат только для обновления | профили и восстановление ломают систему теми же способами |
| Проверять конфигурацию только после запуска | служба уже остановлена; простой вместо отказа до изменения |

## Последствия

- Каждое изменение стоит снимка и перезапуска — секунды и килобайты; приемлемо.
- Каждый новый сценарий обязан вписаться в каркас; сценарий, который нельзя откатить, требует ADR.
- Тесты проверяют провал на каждом шаге ([testing.md](../testing.md) §3).
