# ADR-0038: Исходящий трафик клиентов — запрет порта 25 и BitTorrent

- Статус: Принято (владелец, 2026-11-23; Q14, вариант C)
- Дата: 2026-11-23

## Контекст

Хостеры блокируют VPS за рассылку почты (порт 25) и по жалобам правообладателей (BitTorrent).
Конфигурация пропускает любой исходящий трафик клиентов, кроме частных адресов (ADR-0027).
Условия конкретных хостеров не проверялись — это известная практика, а не датированный факт.

## Решение

- Пресет запрещает соединения клиентов на порт 25 (TCP) любого адреса — правилом маршрутизации
  по порту в `blackhole`.
- Пресет запрещает BitTorrent — правилом маршрутизации по протоколу `bittorrent` в
  `blackhole`. Для определения протокола у входящего `vless` включается `sniffing` только для
  маршрутизации (`routeOnly`): адрес назначения не подменяется.
- Поля, умолчания и поведение `sniffing` и правила `protocol` устанавливаются по скилу
  `xray-upstream` до кода и записываются в [compatibility.md](../compatibility.md) с датой.
- Доказательство (задача A8): эталон проходит `xray run -test`; L3 — соединение на порт 25
  через тоннель не открывается; тест отрисовки падает без правил.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| A. Ничего не запрещать | VPS можно потерять из-за одного профиля |
| B. Только порт 25 | не закрывает жалобы правообладателей — выбор владельца |

## Последствия

- Почтовый клиент на порту 25 через VPN не работает; 587 и 465 работают.
- `sniffing` разбирает начало трафика клиентов: больше работы процессора и новая поверхность
  разбора во входящем. Распознаётся не весь BitTorrent: шифрованный обмен и часть UDP
  проходят — запрет снижает риск жалоб, а не исключает его.
- Пересмотреть, если `sniffing` заметно влияет на ресурсы VPS или ломает клиентов.
