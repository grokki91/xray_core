# ADR-0011: Диагностика — наблюдения, классы выводов, точки наблюдения

- Статус: Принято
- Дата: 2026-11-13

## Контекст

Симптом «не подключается» имеет десятки причин, и с сервера видна только часть. Соблазн —
объявить таймаут блокировкой. Задание требует различать подтверждённые факты, вероятные причины
и гипотезы и не выдавать предположения о DPI за результат, а в перспективе — сравнивать
измерения из разных сетей.

## Решение

- Диагностика разделена на **наблюдения** (что измерено, откуда, с какими ограничениями) и
  **выводы** (утверждения о причине), собранные из наблюдений правилами.
- У вывода обязателен класс: `fact`, `probable`, `hypothesis`; правила присвоения —
  [diagnostics.md](../operations/diagnostics.md) §1. Вывод о сетевой фильтрации никогда не
  получает `fact`, а без внешних точек — выше `hypothesis`.
- Проверки — реестр с единым интерфейсом; движок не знает их содержания.
- **Точка наблюдения** — часть формата: `local`, `probe`, `client`. Внешние точки отдают
  наблюдения того же формата; сравнение — задача анализа.
- Проверка, которой нечем измерить, возвращает `skip` с причиной.
- Отчёт сохраняется и экспортируется только отредактированным.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Проверки сразу печатают вердикт | нельзя сравнить точки, нельзя пересчитать вывод по новым правилам, предположение выглядит фактом |
| Числовая «уверенность» вместо классов | создаёт видимость точности, которой у измерений нет |
| Сторонние сервисы проверки доступности | раскрывают адрес сервера третьей стороне |

## Последствия

- Внешние узлы и `xray_client` подключаются без изменения проверок: добавляется источник
  наблюдений.
- Правила анализа — отдельный тестируемый слой; на каждый класс есть тесты.
- С одной локальной точкой отчёт часто будет честно говорить «не проверено извне» — это
  ожидаемо и лучше ложной определённости.
