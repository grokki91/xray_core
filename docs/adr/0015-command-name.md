# ADR-0015: Имя команды `xm`, без миграции предшественника

- Статус: Принято
- Дата: 2026-11-14

## Контекст

Имя команды входит в каждый документ, юнит, путь и в вызовы со стороны `xray_client`. Его нужно
закрепить до первой строки кода (Q4, часть 1). Там же — переносить ли установку
предшественника (ключи REALITY, UUID клиентов, порт) в новый `xm`. В `grokki91/xray` уже есть Bash-менеджер `xm`, с
которым работает `xray_client`.

## Решение

- Команда нового менеджера — `xm`.
- Миграции нет: `xm` ставится на чистый VPS и выпускает новые ключи; установку предшественника
  не читает, не переносит и не перезаписывает. Клиенты получают новые ссылки.
- Мост для `xray_client` строится к новому `xm`; его формат и имя репозитория остаются в Q4
  ([open-questions.md](../open-questions.md)).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Новое имя | `xray_client` и привычка владельца завязаны на `xm`; выигрыш — только различимость с предшественником, а совместной установки на одном сервере всё равно нет |
| Миграция ключей и клиентов предшественника | второй разборщик чужого формата ради разового переноса; владельцу нужен новый код на чистом сервере |

## Последствия

- Две установки с одним именем команды на одном сервере невозможны; поведение `xm install` на
  сервере с предшественником определяется в фазе 4 вместе с проверкой чужой установки Xray.
- Пересмотреть, если владелец решит поддерживать совместную работу с предшественником.
