# ADR-0036: Установка меняет только своё; чужие правила фаервола — факт и команда

- Статус: Принято (владелец, 2026-11-23; Q7, вариант A, дополнение «а»)
- Дата: 2026-11-23

## Контекст

Предшественник при установке сам ставил fail2ban, UFW, chrony, автообновления ОС и правил SSH.
Ошибка в SSH или фаерволе отрезает владельца от сервера — это приоритет 1. Образы хостеров
бывают с правилами nftables или iptables, закрывающими всё, кроме SSH (задача A3).

## Решение

- `xm install` меняет только своё: пользователь, каталоги, юнит, конфигурация. Пакеты не
  ставит, настройки SSH не трогает, фаервол не включает.
- UFW уже активен — `xm install` добавляет правило, разрешающее входящий порт Xray, в
  транзакции; кто ставит, снимает и откатывает правило — ADR шага 5 фазы 4.
- UFW не активен, а входящий порт закрывают правила nftables или iptables — `xm install` их не
  меняет: итог называет факт и команду, которая откроет порт. Не удалось определить — итог
  говорит «не определено»; вывод о фаерволе хостера — не выше гипотезы.
- Усиление SSH и фаервола — отдельная команда `xm harden` (после MVP, свой ADR) с защитой от
  потери доступа ([policy.md](../security/policy.md) §7). Итог установки может её назвать.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| B. Всё автоматически, как у предшественника | правка SSH и включение фаервола без проверки — риск потери доступа; установка пакетов без вопроса |
| A(б). Добавлять правило nftables или iptables самому | чужой набор правил разнообразен; ошибка в нём рвёт доступ; откат хрупок |

## Последствия

- На образе с закрытым портом установка заканчивается командой, которую владелец выполняет сам.
- Сервер без `xm harden` защищён настолько, насколько его оставил хостер.
- Пересмотреть, если L4 и отчёты покажут, что команда для nftables стабильно одна и та же.
