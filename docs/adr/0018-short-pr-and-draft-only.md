# ADR-0018: Короткое описание PR; агент — только черновики

- Статус: Принято
- Дата: 2026-11-15

## Контекст

Описания PR разрослись: разделы «Зачем», «Проверка», «Чек-лист» повторяют то, что уже
гарантируют `scripts/check.sh`, хуки и ревью. Владелец читает PR ради сути. В `main` ничего не
должно попадать без его решения.

## Решение

- Тело PR — по `.github/PULL_REQUEST_TEMPLATE.md`: раздел «Что сделано» короткими тезисами и,
  только если есть, «Не проверено» с командой проверки.
- Агент создаёт PR сам, но только черновиком. Перевод в Ready for review и слияние, в том числе
  автослияние, — только владелец.
- Правило проверяет хук `publish-guard.sh`: отказ при создании PR не черновиком, переводе в
  ready, слиянии и автослиянии (GitHub MCP, `gh pr`, изменяющий `gh api`), при `gh alias`, при
  push и записи файлов в `main`.
- Подпись ассистента в теле PR этот ADR не регулирует (Q12).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Оставить полный шаблон | владелец счёл его слишком длинным |
| Подтверждение владельца на каждое создание PR | владелец разрешил агенту создавать PR сам; граница — ready и слияние |
| Только правило в `AGENTS.md` | инструкция может уступить настройке инструмента; хук срабатывает всегда |

## Последствия

- Итоги проверок в PR не пишутся. Цена: до CI (шаг 3 фазы 1, ADR-0016) зелёный
  `scripts/check.sh` подтверждён только для правок через Claude Code, где его требуют хуки.
- Хук — защита в Claude Code; для любых инструментов слияние в `main` закрывает защита ветки в
  настройках GitHub, которую включает владелец.
- Хук разбирает команду регулярными выражениями: это защита от ошибки агента, а не от
  намеренного обхода. Гарантию для любых инструментов даёт только защита ветки на GitHub.
