# ADR-0022: Журнал `xm` — запись в journald через `platform`

- Статус: Принято
- Дата: 2026-11-16

## Контекст

Журнал `xm` — journald с идентификатором `xm`, собственных файлов нет
([data-model.md](../architecture/data-model.md) §1). `xm` — короткая команда, а не служба: её
stderr в journald не попадает. Порт `platform` писать в journald не умел; побочные эффекты
разрешены только в нём.

## Решение

- `Platform.Journal()` — запись `Write(Priority, message)` в сокет `/run/systemd/journal/socket`
  по родному протоколу journald: `SYSLOG_IDENTIFIER=xm`, `PRIORITY`, `MESSAGE`. Идентификатор
  задаёт `platform`, вызывающий его не меняет.
- Сообщение длиннее 4096 байт обрезается; перевод строки передаётся двоичной формой поля.
- Сокета нет или запись не удалась — ошибка вызывающему, без запасного вывода в stderr.
- `logging.Logger()` — `slog` поверх редактора: каждая запись целиком проходит `redact.Text`
  до записи в `Journal`.
- Выбор владельца 2026-11-16 (вопрос к шагу 5 фазы 2).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| `systemd-cat` через `Exec` | новая программа в закрытом списке, процесс на каждую запись |
| только stderr | команды `xm` в journald не попадают; расходится с data-model §1 |

## Последствия

- Вне systemd (контейнер без journald, тесты) настоящий `Journal` возвращает ошибку; тесты
  используют `Fake`, который записывает вызовы.
- Пересмотреть, если появится второй получатель журнала или понадобятся поля, кроме трёх.
