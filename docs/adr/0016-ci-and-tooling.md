# ADR-0016: CI и инструменты проверки

- Статус: Принято
- Дата: 2026-11-14

## Контекст

Обязательные проверки собраны в `scripts/check.sh`, но запускаются автоматически только хуками
Claude Code; люди и другие инструменты их минуют, а без конвейера невозможен выпуск (ADR-0013).
Оценка инструментов — [tooling.md](../dev/tooling.md); ответ владельца по каждой строке — Q5.

## Решение

- **CI** — GitHub Actions: `bash scripts/check.sh` на каждый PR и на `main`; проверка
  обязательна для слияния в `main`. Правила конвейера — [policy.md](../security/policy.md) §6.
- **Secret scanning и push protection** GitHub — включает владелец в настройках репозитория.
- **gitleaks, govulncheck, staticcheck, shellcheck** — шагами того же workflow, с фиксированной
  версией; в поставку `xm` не попадают. gitleaks — без своих списков разрешённых значений и
  без строчных пометок-исключений ([secrets.md](../security/secrets.md) §4).
- **Dependabot** — нет: зафиксированные версии и хэши обновляются вручную по правилу реестра.
- **Подтверждение происхождения сборки** (artifact attestations) — да, в фазе 4 с первым выпуском.
- **Позже**: клиентские ядра в тестах, CodeQL, автоматическое ревью PR агентом — после MVP;
  RealiTLScanner — вместе с Q3; системы спецификаций — пересмотреть после MVP.
  **Не подключать**: остальное из [tooling.md](../dev/tooling.md) §5.
- Согласованный инструмент — строкой в [dependencies.md](../dev/dependencies.md) §3; подключённым
  он становится с появлением в workflow.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Без CI, только `scripts/check.sh` и хуки | хуки защищают лишь сессии Claude Code; без конвейера нет выпуска |
| Dependabot | шум PR ради нескольких фиксаций; владелец выбрал ручное обновление |
| Только `scripts/guard.sh` без gitleaks | свой сканер знает данные установки, но не сотни форматов чужих токенов |
| Готовое действие gitleaks | для организаций требует секрет лицензии; бинарник с проверкой суммы проще |

## Последствия

- Проверка PR больше не зависит от того, чем сделан коммит; красный `check.sh` не сливается.
- Зафиксированные хэши и версии устаревают молча: их сверяют при каждой правке workflow.
  Пересмотреть отказ от Dependabot, если устаревшая фиксация пропустит уязвимость или ручные
  обновления станут регулярной работой.
- Конвейер обращается к внешним адресам (модули Go, база уязвимостей, релизы сканеров) — они
  в реестре, а не в §5: это адреса CI, не `xm`.
