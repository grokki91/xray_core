# ADR-0025: Остановленная служба в транзакции и сценарий `xm install` фазы 2

- Статус: Принято
- Уточняет: [ADR-0023](0023-transaction-control-and-rollback-scope.md)
- Дата: 2026-11-16

## Контекст

`app.Apply` всегда перезапускал службу и проверял её. После `xm stop` любое изменение (будущие
`xm add`, `xm rm`, обновление) молча подняло бы VPN, который владелец остановил намеренно
(задача A5 аудита). Шаг 10 фазы 2 добавляет первый сценарий — `xm install` — и команды службы.
Выбор владельца 2026-11-16 (шаг 10 фазы 2).

## Решение

- **Остановленная служба остаётся остановленной.** Транзакция запускает службу, если она была
  активна до изменения или юнита не было вовсе (новая установка); иначе перезапуска и контроля
  «служба работает» нет. Остальные шаги — проверка `xray run -test`, запись, фиксация — как
  обычно, изменение вступает в силу после `xm start`. Откат такой службы её тоже не запускает
  (ADR-0023).
- **`xm start`, `stop`, `restart` — не транзакции.** Они берут блокировку, сначала откатывают
  незавершённую транзакцию, затем выполняют действие и контроль (`CheckRunning` или
  `CheckStopped`). Провал контроля — ошибка с кодом 1, откатывать нечего.
- **Базовая защита — внутри транзакции**, до отката незавершённой и снимка: каждое изменение
  системы проверяет манифест прав (политика [policy.md](../security/policy.md) §2); чужие права
  не исправляются молча, сбой — отказ до любого изменения.
- **`xm install --sni <домен> --address <адрес> [--port <порт>]`** (порт по умолчанию 443; оба
  параметра обязательны до фазы 4). Порядок: проверка ввода → предусловия → отказ, если состояние
  уже есть → последний стабильный релиз, загрузка, сверка сумм, `Stage` → ключи → транзакция
  (состояние без профилей, конфигурация, юнит, запуск, контроль). Цель REALITY — `<sni>:443`
  (автоматический выбор — Q3, фаза 4). Версия, выложенная прошлой неудачной установкой, используется
  повторно: она уже прошла `Stage`, `Activate` проверит её ответ.
- **Повторная установка** на своей установке — отказ (код 3): идемпотентность — шаг 5 фазы 4.
- **Корень обязателен** для `install`, `start`, `stop`, `restart` и `status`: состояние и systemd
  доступны только root; без root — код 3 `preflight.not_root`.
- **Вывод.** `status` — схема `status` ([interfaces.md](../architecture/interfaces.md) §2); `install` и
  команды службы машинного вывода не имеют. Сообщения об ошибках идут в stderr через редактор;
  адрес сервера печатают `install` и `status` — это их назначение.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Транзакция всегда запускает службу | `xm stop` перестаёт значить «остановлено»; нужен только текст предупреждения |
| Отказ изменять при остановленной службе | владельцу нельзя настроить сервер, не включая VPN |
| Базовая защита только в `install` | политика обещает проверку при каждой транзакции; дрейф прав остаётся незамеченным |
| `start`/`stop` как транзакции | снимок без изменения данных (ADR-0023) |

## Последствия

- Сообщение «служба остановлена, изменение вступит в силу после `xm start`» — у команд фазы 3
  (`add`, `rm`); `Apply` пока не возвращает признак запуска — его добавит первый потребитель.
- Служба в состоянии `failed` считается неработавшей: транзакция её не запускает, владелец
  запускает её сам.
- Поведение счётчика `NRestarts` после ручного перезапуска на systemd 249 и 255 — факт для
  `compatibility.md` и системного теста L4 (шаг 11, A5): он не проверен.
- Две одновременные установки сходятся на блокировке `Apply`, но проверка «состояния нет» идёт до
  неё; повторную установку фаза 4 сделает идемпотентной под блокировкой.
