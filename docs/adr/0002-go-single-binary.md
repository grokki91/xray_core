# ADR-0002: Go, один статический бинарник

- Статус: Принято
- Дата: 2026-11-13

## Контекст

Нужен язык для менеджера на VPS с 1 vCPU и 2 ГБ RAM: без тяжёлых зависимостей, с жёсткими
границами модулей, удобный для разработки силами LLM. Предшественник на Bash вырос в один файл
на 7 тыс. строк без модульных тестов.

## Решение

- Менеджер `xm` пишется на Go и поставляется одним статическим бинарником (`CGO_ENABLED=0`).
- Цель — ноль сторонних модулей в поставке; каждое исключение проходит
  [реестр зависимостей](../dev/dependencies.md).
- Bash — только для загрузчика `install.sh` и скриптов разработки.
- Web UI — статические файлы без сборки, встроенные в бинарник.

Сравнение вариантов и недостатки выбранного — [stack.md](../architecture/stack.md).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Bash | не масштабируется по сложности, нет типов и изоляции модулей, высокий риск ошибок подстановки |
| Python | версия интерпретатора зависит от релиза ОС; внешние библиотеки требуют `pip` на VPS |
| Rust | медленнее цикл разработки; выигрыш в памяти не нужен процессу, который не работает постоянно |

## Последствия

- Нужен конвейер выпуска и проверка целостности бинарника при установке
  ([ADR-0013](0013-distribution-and-bootstrap.md)).
- Общий язык с Xray-core и `xray_client` упрощает общий контракт и тестовые стенды.
- Пересмотреть, если бюджеты памяти или размера из [overview.md](../architecture/overview.md) §8
  окажутся недостижимы.
