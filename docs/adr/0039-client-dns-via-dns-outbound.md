# ADR-0039: Запросы клиентов на :53 — исходящий `dns` с явными правилами

- Статус: Принято (владелец, 2026-11-24)
- Уточняет: [ADR-0027](0027-private-destinations-via-final-rules.md), [ADR-0034](0034-own-final-rules-over-upstream-default.md)
- Дата: 2026-11-24

## Контекст

Запросы клиентов к DNS внутри тоннеля должен отвечать встроенный DNS Xray через DoH
(components.md, раздел `dns`). Встроенный DNS сам порт 53 не перехватывает: нужен исходящий `dns`
и правило маршрутизации. Запрет частных адресов (ADR-0027) — `finalRules` у `freedom`; к
исходящему `dns` он не применяется ([compatibility.md](../compatibility.md) §2).

## Решение

- При разделе `dns` конфигурация содержит исходящий `dns-out` и единственное правило
  маршрутизации: порт `53`, `tcp,udp` → `dns-out`. Без раздела `dns` нет ни того, ни другого.
- У `dns-out` явные `settings.rules`: `hijack` для A и AAAA (ответ встроенного DNS), `return` с
  `rCode: 5` (REFUSED) для остального. Действия `direct` нет: исходящий `dns` соединяется с адресом
  назначения только при `direct`, поэтому на адрес, указанный клиентом, не уходит ни один пакет.
- Устаревшее `nonIPQuery` не используется.
- Доказательство — L3 на трафике: запросы A и TXT через тоннель на `127.0.0.1:53` не доходят до
  слушателя; A получает ответ встроенного DNS, TXT — REFUSED; без правил тест падает.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Без `dns-out` | `:53` уходит через `freedom` на адрес клиента — мимо DoH сервера |
| `dns-out` без `settings` | поведение зависит от умолчания upstream (принцип ADR-0034) |
| `nonIPQuery: reject` | поле устарело и несовместимо с `rules` |

## Последствия

- Запросы TXT, MX, SRV и подобные через тоннель получают отказ.
- UDP в L3 не проверен: клиент теста передаёт только TCP.
- Пересмотреть, если клиентам понадобятся типы запросов кроме A и AAAA или upstream изменит
  правила исходящего `dns`.
