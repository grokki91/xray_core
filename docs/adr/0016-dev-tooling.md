# ADR-0016: Инструменты разработки и CI

- Статус: Принято
- Дата: 2026-11-14

## Контекст

Обязательные проверки работают только локально: хуки Claude Code и `scripts/check.sh`. Без CI
их обходит любой коммит не из сессии, а фаза 4 невыполнима — нужен конвейер выпуска. Оценка
каждого инструмента — [tooling.md](../dev/tooling.md); владелец принял предложения §1 целиком
(вопрос Q5).

## Решение

- Подключаются: GitHub Actions с `scripts/check.sh` на PR и `main`; secret scanning и push
  protection GitHub; gitleaks, govulncheck, staticcheck, shellcheck, Dependabot — в фазе 1;
  подтверждение происхождения сборки — в фазе 4, с первым выпуском.
- Действия CI фиксируются по хэшу коммита, права заданий — `contents: read`, секретов в
  заданиях проверок нет; инструменты — с зафиксированной версией. Обновления Dependabot не
  сливаются автоматически.
- Рассматриваются позже, отдельным решением: бинарники клиентских ядер в тестах, CodeQL —
  после MVP; RealiTLScanner — вместе с Q3.
- Пересматриваются после MVP: OpenSpec и Spec Kit, ревью PR агентом в CI.
- Не подключаются: golangci-lint, GoReleaser, cosign, trivy, osv-scanner, pre-commit,
  go-arch-lint, depguard, агентные фреймворки, дополнительные MCP-серверы.
- Согласие на инструмент — строка в [dependencies.md](../dev/dependencies.md) §3; в
  конвейере нет инструмента без строки.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Без CI | проверки обходятся; системные тесты фазы 2 — только вручную; выпуск невозможен |
| Только CI, без сканеров | govulncheck и gitleaks закрывают классы ошибок, которых нет в `check.sh` |

## Последствия

- Проект зависит от GitHub Actions; чужой код в конвейере ограничен фиксацией по хэшу.
- Secret scanning и push protection включает владелец в настройках репозитория: у агента
  нет доступа к ним.
- Пересмотреть, если CI станет дольше 10 минут на PR или ложные срабатывания сканеров
  начнут обходиться вместо исправления.
