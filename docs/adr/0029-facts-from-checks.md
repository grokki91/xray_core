# ADR-0029: Факт строит проверка, предположения — правила анализа

- Статус: Принято (владелец, 2026-11-18)
- Уточняет: [ADR-0011](0011-diagnostics-evidence-model.md), [ADR-0024](0024-health-verdict-and-shared-checks.md)
- Дата: 2026-11-18

## Контекст

ADR-0011 говорит, что выводы собирают правила анализа, но не называет, кто строит вывод класса
`fact`. Вердикт ADR-0024 стоит только на фактах: если провал измерения не дал факта, вердикт
молча остаётся `ok`. Первопричина должна быть фактом без проваленных зависимостей.

## Решение

- Вывод `fact` строит только проверка — по своему наблюдению `fail`, вместе с влиянием на
  подключение: `down` или `degraded`. Ссылку на наблюдение и класс ставит движок.
- Правила анализа строят только `probable` (с альтернативами) и `hypothesis` (с тем, что
  подтвердит и что опровергнет); влияния у них нет. Правило, вернувшее `fact` или неполный
  вывод, — ошибка программы.
- Наблюдение `fail` без факта с влиянием движок считает сломанным: исход `error`, а не `fail`.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Факты, как и прочие выводы, строят правила; влияние ставит правило | провал без правила молча даёт `ok`; нужна вторая страховка — `unknown` при `fail` без факта |
| Влияние — свойство проверки, факт строит правило вердикта | текст и действие факта всё равно знает только проверка — два места на одно знание |

## Последствия

- У каждого провала есть факт; вердикт не может пропустить провал.
- Факт из нескольких наблюдений разных проверок невозможен: такая картина — `probable`.
- Пересмотреть, если появится факт, который прямо следует только из сочетания проверок.
