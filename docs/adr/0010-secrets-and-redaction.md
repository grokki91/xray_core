# ADR-0010: Секреты только на VPS; редактор на границе

- Статус: Принято
- Дата: 2026-11-13

## Контекст

Репозиторий публичный, разработка идёт через LLM, диагностика по своей природе собирает адреса и
идентификаторы. Утечка возможна в любой точке: фикстура, журнал, отчёт, сообщение коммита,
переписка с агентом. Набор мелких сведений об установке опасен так же, как ключ.

## Решение

- Секреты создаются на VPS одним пакетом (`security`) и хранятся в состоянии с правами `0600`.
- На границе «система → человек или файл» стоит обязательный редактор (`redact`): реестр точных
  значений из состояния плюс шаблоны. Журнал, отчёт диагностики, экспорт и сообщения об ошибках
  проходят его всегда.
- Секрет показывается только командой, чьё назначение — его показать.
- В репозитории — только фиктивные значения по одной таблице; сканер и хуки не дают записать и
  опубликовать иное. Исключений и списков «разрешённых» реальных значений нет.
- Данные с сервера выносятся только отредактированным экспортом.

Полные правила — [secrets.md](../security/secrets.md).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Редактировать только при экспорте | секреты уже осели в журналах и сохранённых отчётах |
| Только шаблоны (регулярные выражения) | пропускают домены, пути, shortId; точные значения из состояния ловят всё своё |
| Полагаться на внимательность | не работает с агентами, читающими и пишущими тысячи строк |
| Внешний менеджер секретов | зависимость и сеть ради одного файла на одном сервере |

## Последствия

- Каждый новый вид секрета требует регистрации в редакторе и канареечного теста.
- Отредактированные отчёты менее удобны для ручного разбора: метки стабильны в пределах отчёта,
  чтобы связи между строками сохранялись.
- Сканер иногда остановит безобидное (версию, похожую на адрес): убирается из текста, а не
  добавляется в исключения.
