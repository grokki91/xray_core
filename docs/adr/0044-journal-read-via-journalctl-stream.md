# ADR-0044: Чтение журнала — `journalctl` через `platform.Stream`

- Статус: Принято
- Дата: 2026-11-26

## Контекст

`xm logs [-f] [--since]` показывает журнал Xray и `xm` из journald (фаза 5, шаг 6). `Exec`
копит вывод целиком до выхода процесса, а `-f` не кончается; `Start` вывод отбрасывает.
Читать journald без внешней программы — значит разбирать его двоичные файлы.

## Решение

- `journalctl` (`/usr/bin/journalctl`) — в закрытом списке программ; только чтение.
- `Platform.Stream(ctx, Command) (io.ReadCloser, error)` — правила `Exec` (без оболочки, своё
  окружение, группа процессов, срок обязателен), stdout отдаётся потоком без предела, stderr
  отбрасывается; ненулевой код — ошибка в конце чтения; `Close` убивает группу процессов.
- Аргументы фиксированы: `--output=json`, поля время, идентификатор и сообщение (имя узла не
  читается), совпадение `_SYSTEMD_UNIT=xray.service + SYSLOG_IDENTIFIER=xm`; без `--since` —
  последние 200 записей.
- `--since` — `N` m|h|d (1–9999) или `ГГГГ-ММ-ДД`; переводится в абсолютное время UTC, ввод
  владельца в аргумент не попадает.
- Каждая запись — строка «время UTC источник: сообщение»: управляющие символы заменяются `?`,
  строка проходит `redact.Text`; двоичное сообщение не показывается.
- `-f` ограничен сроком 24 ч; и он, и Ctrl-C — обычный конец (код 0).
- Выбор владельца 2026-11-26.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| `Exec` без `-f` | расходится с командой `xm logs -f` в interfaces.md |
| свой разбор файлов journald | большой хрупкий разборщик чужого формата |
| `-o short-iso` | в строке имя узла — данные установки |

## Последствия

- Вне systemd `xm logs` возвращает ошибку `journalctl`; тесты используют `Fake.HandleStream`.
- Пересмотреть, если `journalctl` поменяет формат `-o json` или понадобятся другие источники.
