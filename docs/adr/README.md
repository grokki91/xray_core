# Записи архитектурных решений (ADR)

Одно решение — один короткий файл: контекст, решение, альтернативы, последствия. Архитектурные
документы описывают, что получилось; ADR — почему. Когда нужен ADR и как его писать — скил `adr`
(`.claude/skills/adr/SKILL.md`), шаблон — [0000-template.md](0000-template.md).

Статусы:

- **Принято** — действует. В PR фазы 0 это решения, принятые в рамках задания; они вступают в
  силу со слиянием PR, и владелец может вернуть любое на обсуждение.
- **Ждёт решения** — рекомендация записана, выбор за владельцем (номер вопроса в
  [open-questions.md](../open-questions.md)).
- **Заменено ADR-NNNN**, **Отклонено** — для истории; файл не удаляется.

Принятый ADR не переписывается: решение меняется новым ADR.
