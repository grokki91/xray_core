# ADR-0019: Запуск Xray по версии и ссылка `current`

- Статус: Принято
- Дата: 2026-11-16

## Контекст

`core` хранит версии Xray в `/usr/local/lib/xm/core/<версия>/xray` и переключает активную
ссылкой `current` ([data-model.md](../architecture/data-model.md) §1). Порт `platform` знал
только программы «имя → один путь» и отвергал символические ссылки на любом пути. Проверить
ещё не активную версию (`xray version`, `xray run -test`) и атомарно переключить `current`
этим портом нельзя.

## Решение

- `Command.Version` — только у программы `xray`: `platform` проверяет версию по правилу
  `N.N.N` и сам строит путь `/usr/local/lib/xm/core/<версия>/xray`. У `xray` без версии и у
  прочих программ с версией — `ErrProgram`. `xm` всегда вызывает Xray по явной версии; через
  `current` его запускает только systemd.
- `FS.Symlink(path, target)` — атомарно: временная ссылка в том же каталоге и `rename`. Цель —
  одно имя в том же каталоге (без `/`, не `.` и `..`): ссылка не уводит за каталог.
  `FS.Readlink(path)` читает только ссылку. Остальные операции `FS` по-прежнему отвергают
  ссылку на пути; бинарник `xray` запускается, только если путь к нему без ссылок.
- Выбор владельца 2026-11-16 (вопросы к шагу 3 фазы 2).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Разрешить запуск любого файла под `/usr/local/lib/xm/core/` | список перестаёт быть закрытым по имени |
| `current` — файл с номером версии, юнит переписывается при переключении | переключение перестаёт быть одной атомарной операцией; меняется раскладка |

## Последствия

- Ввод версии из командной строки доходит до пути программы только через правило `N.N.N`.
- Прочитать файл через `current` (`ReadFile`) нельзя — и не нужно: `xm` знает версию.
- Пересмотреть, если появится второй управляемый бинарник с версиями.
