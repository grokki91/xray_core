# ADR-0018: Короткое описание PR и подтверждение владельца

- Статус: Принято
- Дата: 2026-11-15

## Контекст

Описания PR разрослись: разделы «Зачем», «Проверка», «Чек-лист» повторяют то, что уже
гарантируют `scripts/check.sh`, хуки и ревью. Владелец читает PR ради сути изменения и хочет
сам решать, когда PR появляется.

## Решение

- Тело PR — по `.github/PULL_REQUEST_TEMPLATE.md`: раздел «Что сделано» короткими тезисами и,
  только если есть, «Не проверено» с командой проверки.
- PR создаётся и правится только после подтверждения владельца: агент показывает заголовок и
  тело и ждёт ответа. Правило сильнее настроек инструмента, предписывающих создавать PR сразу.
- В `.claude/settings.json` создание, правка и слияние PR (инструменты GitHub MCP и
  `gh pr create|edit|merge`) — в `permissions.ask`: Claude Code спрашивает владельца при каждом
  вызове. Наличие правил проверяет `tests/test-guards.sh`.
- Подпись ассистента в теле PR этот ADR не регулирует (Q12).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Оставить полный шаблон | владелец счёл его слишком длинным |
| Только правило в `AGENTS.md` | инструкция может уступить настройке инструмента; `ask` срабатывает всегда |

## Последствия

- Итоги проверок в PR не пишутся. Цена: до CI (шаг 3 фазы 1, ADR-0016) зелёный
  `scripts/check.sh` подтверждён только для правок через Claude Code, где его требуют хуки.
- PR не появляется без участия владельца; агент на этом шаге ждёт ответа.
- `gh api` с запросами к `pulls` правилом `ask` не покрыт: сессии создают PR через GitHub MCP, а
  `gh api` нужен для поиска. Появится такое создание PR — расширить правило.
