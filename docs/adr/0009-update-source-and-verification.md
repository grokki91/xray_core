# ADR-0009: Источник и проверка обновлений Xray

- Статус: Принято (автообновление — вопрос Q9)
- Дата: 2026-11-13

## Контекст

Xray — сетевая служба с правом слушать порт; его бинарник скачивается из интернета. Upstream
публикует к архиву файл `.dgst` с хэшами, но не подписи. Официальный установочный скрипт сверяет
только SHA-256 и не умеет откат. Обновление сервера способно отрезать клиентов.

## Решение

- Источник — только релизы `XTLS/Xray-core`; адреса загрузки — закрытый список; только HTTPS;
  только стабильные релизы.
- Загрузку и проверку выполняет `xm` сам: SHA2-256 и SHA2-512 из `.dgst`, проверка ELF и
  ответа `xray version`, защита распаковки.
- `xm` знает **проверенный диапазон версий** Xray; `xm update` не выходит за него без
  `--to <версия>`.
- Перед переключением новая версия проверяет действующую конфигурацию (`xray run -test`); после —
  контроль и автоматический откат на сохранённую предыдущую версию.
- Автоматического обновления по расписанию в MVP нет.

Порядок и ограничения — [updates.md](../operations/updates.md).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Официальный `install-release.sh` | исполнение непроверенного скрипта от root; нет отката; меняет юнит и раскладку по-своему |
| Пакет из репозитория ОС | версии отстают на месяцы |
| Всегда последняя версия | повторяет случай с X25519MLKEM768: клиенты отваливаются без предупреждения |
| Только SHA-256 | второй хэш почти бесплатен |

## Последствия

- Выпуск новой версии Xray требует прогона тестов и расширения диапазона в `xm` — регулярная
  работа; она же — место, где обновляется таблица совместимости.
- Проверка не защищает от скомпрометированного релиза upstream; это названо в модели угроз (T8).
- Геоданные не используются и не обновляются.
