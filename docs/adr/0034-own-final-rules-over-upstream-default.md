# ADR-0034: Свой запрет частных адресов при встроенном запрете upstream

- Статус: Принято (владелец, 2026-11-21)
- Уточняет: [ADR-0027](0027-private-destinations-via-final-rules.md)
- Дата: 2026-11-21

## Контекст

ADR-0027 требует теста на трафике, который падает без правила `finalRules`. В обеих границах
проверенного диапазона `freedom` для соединений с входящего `vless` сам блокирует частные
адреса встроенным правилом после явных ([compatibility.md](../compatibility.md) §2). Без нашего
правила запрос к петле всё равно не доходит, и такой тест упасть не может.

## Решение

- Явное правило `finalRules` из ADR-0027 остаётся: запрет не зависит от умолчаний upstream.
- Доказательство разделено. L3 на трафике: запрос через тоннель к петлевому адресу, к `0.0.0.0`,
  к имени, разрешающемуся в петлю, и к частному адресу машины не доходит до слушателя; контроль
  — тот же сервер с `allow` для петли перед запретом пропускает запрос. «Падает без правила» —
  тест отрисовки конфигурации (L2).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Положиться на встроенный запрет, своё правило убрать | безопасность зависит от умолчания upstream, которое меняется между версиями |
| Взять встроенный список сетей вместо своего | список различается в границах диапазона |

## Последствия

- Часть нашего списка дублирует встроенный; встроенный шире.
- Пересмотреть, если upstream уберёт встроенный запрет или изменит порядок правил.
