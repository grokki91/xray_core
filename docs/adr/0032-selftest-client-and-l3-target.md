# ADR-0032: Самопроверка — служебный клиент, процесс клиента Xray и цель L3

- Статус: Принято
- Уточняет: [ADR-0020](0020-l3-stand.md), [ADR-0024](0024-health-verdict-and-shared-checks.md), [ADR-0028](0028-qr-library-and-selftest-address.md)
- Уточнён: [ADR-0033](0033-selftest-only-in-change-control.md) — самопроверка только в контроле изменения, `skip` не провал
- Дата: 2026-11-19

## Контекст

Шаг 7 фазы 3: `reach.selftest` и сквозной тест L3. Сервер блокирует петлевые и частные адреса
([ADR-0027](0027-private-destinations-via-final-rules.md)) — локальный HTTP-сервер недостижим; у
самопроверки нет клиента; `platform` только ждёт процесс, `Net.Get` — ответ 200 без своего
прокси. Варианты выбрал владелец 2026-11-19.

## Решение

- **Служебный клиент** `selftest.id` в состоянии: не профиль — `config` отрисовывает его во
  входящих, `list`, `status`, экспорт профилей и `rm` его не показывают. Класс S1, в редакторе как
  UUID, входит в снимки. Одно правило: транзакция `app` с пустым полем заполняет его через
  `security.NewClientID` (установка — тоже); миграция `store` 1 → 2 оставляет поле пустым.
- **Конфигурация клиента** — `config.RenderClient(st, id, socket)`: из состояния, как и ссылка;
  входящий — HTTP на сокете Unix по пути `socket`. Разборщика ссылок в боевом коде нет; L3
  сверяет параметры экспортированной ссылки с параметрами клиента.
- **Процесс.** `platform.Start(ctx, Command) (Process, error)`: фон, срок в контексте обязателен,
  группа процессов и пределы — как у `Exec`; остановка по контексту или `Stop`. `Fake.Start`
  запускает настоящий файл под корнем подделки, как `RunUnderRoot`. Метод `core` — `xray run`
  действующей версией, конфигурация через stdin, от root, как `run -test`.
- **Запрос.** `platform.Request` получает поля `Proxy` (сокет Unix; окружение не действует) и
  ожидаемый код ответа; закрытый список узлов сверяется с узлом назначения.
- **Измерение целиком** — проверка `reach.selftest` в `diag` ([ADR-0030](0030-diag-checks-in-package.md)):
  удалить прежний сокет `/run/xm/selftest.sock` (в L3 — во временном каталоге), запустить клиента,
  дождаться сокета, запросить адрес, остановить; всё — интерфейсами потребителя, `app` их только
  подставляет. Зависит от `reach.listen`, входит в `control`; `fail` — факт `down`; адрес
  недоступен с VPS — `skip` или `error` с причиной, не вывод о фильтрации.
- **Цель L3** — `cp.cloudflare.com/generate_204`; сервер отрисован из состояния без правок; тот
  же стенд проверяет, что запрос к `127.0.0.1` не доходит (A1).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Первый профиль вместо служебного клиента | без профилей или с отключённым самопроверка не измеряет — `unknown` |
| Разбор экспортированной ссылки в клиент | второй источник параметров и разборщик URI в боевом коде |
| `Exec` со сроком вместо `Start` | истечение срока неотличимо от сбоя процесса |
| Входящий SOCKS на `127.0.0.1` | открытый порт на петле, доступный любому пользователю машины |
| L3 снимает запрет частных адресов | проверяется не боевая конфигурация |

## Последствия

- Утечка `selftest.id` возможна только с состоянием, где уже лежат ключи REALITY; отдельного
  перевыпуска нет — пересмотреть вместе с `install --reinstall`.
- L3 зависит от доступности Cloudflare из CI. Факты upstream (HTTP-входящий на сокете Unix,
  `run` с конфигурацией через stdin) — до кода; не подтвердятся — новый ADR.
