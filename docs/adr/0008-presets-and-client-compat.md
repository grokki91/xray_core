# ADR-0008: Пресеты и совместимость клиентов данными

- Статус: Ждёт решения (Q1, Q2)
- Дата: 2026-11-13

## Контекст

Пользователь не должен выбирать протоколы, но выбор существует: транспорт, параметры REALITY,
формат ссылки. Совместимость клиентов меняется от версии к версии: с v26.9.9 Xray отвергает
ClientHello без X25519MLKEM768, и клиенты на upstream sing-box перестали подключаться
([compatibility.md](../compatibility.md) §3).

## Решение

- **Пресет** — именованная готовая комбинация «протокол + транспорт + защита», единица
  расширения в `config/preset`. Пользователь видит имя пресета, а не поля Xray.
- **Экспорт** профиля — только через экспортёры `profile/export`: одна реализация на формат,
  общая для CLI, панели и моста.
- **Совместимость** — таблица данных «клиент × версия × пресет → подключается ли, с какой версии,
  источник, дата». Экспорт под несовместимую пару — ошибка с причиной; `xm status` показывает
  минимальные версии клиентов. Никаких «приблизительных» ссылок и скрытых подстановок.
- В MVP — один пресет. Рекомендация: `reality-xhttp` (VLESS + REALITY + XHTTP на порту 443).
- Upstream sing-box: рекомендация — принять несовместимость и показывать её в продукте;
  поддерживаемый путь для экосистемы sing-box — Hiddify 5.x.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Свободная настройка полей Xray | противоречит цели «не разбираться в сетевой конфигурации» |
| Знание о клиентах в коде условиями | устаревает молча; данные с датой видно и можно проверить |
| Понизить версию Xray ради sing-box | отказ от исправлений безопасности |
| Пресет без REALITY для sing-box в MVP | отдельная подсистема (домен, сертификаты или другой протокол); только после решения Q2 |

## Последствия

- Новый протокол upstream — новый пресет, поддержка в экспортёрах и строки таблицы; ядро не
  меняется.
- Таблицу совместимости нужно сопровождать: порядок — [compatibility.md](../compatibility.md) §4.
- До ответа на Q1 код пресета не пишется; архитектура от выбора не зависит.
