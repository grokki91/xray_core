# ADR-0031: Токен API GitHub из окружения

- Статус: Принято (владелец, 2026-11-18)
- Дата: 2026-11-18

## Контекст

`xm install` и `xm update` берут тег и SHA-256 файлов последнего релиза из API GitHub
([ADR-0009](0009-update-source-and-verification.md)). Без авторизации у одного внешнего адреса —
60 запросов в час; исполнители CI и VPS за общим NAT делят адрес с чужими клиентами. 2026-11-18
задание `l4 (ubuntu-24.04)` дважды упало на `api.github.com: ответ 403`; исчерпание лимита —
вероятная причина, текста ответа в журнале нет. Отказаться от API нельзя: без него остаётся одна
сумма из `.dgst` с того же узла, что и архив.

## Решение

- Необязательная переменная окружения `XM_GITHUB_TOKEN` процесса `xm`. Задана — запрос к
  `api.github.com` идёт с заголовком `Authorization: Bearer <токен>`; не задана — без него.
  Других источников токена (флаг, файл, состояние) нет.
- Формат проверяется до использования: 40–255 символов `[A-Za-z0-9_]`; иначе команда, которой
  нужен релиз, завершается ошибкой без значения в тексте. Нижняя граница — длина токенов
  GitHub: короткое значение редактор заменял бы во всём выводе.
- Токен уходит только в первый запрос к узлу API: в перенаправления, на `github.com` и узел
  раздачи файлов — нет. Заголовок ставит `platform` по полю запроса; узел и его список не
  меняются ([dependencies.md](../dev/dependencies.md) §5).
- Токен — учётные данные класса S1 ([secrets.md](../security/secrets.md) §1): живёт только в
  памяти процесса, не пишется на диск, в журнал и ошибки; в редакторе регистрируется только значение по формату.
  Дочерние процессы его не получают: их окружение — фиксированный список `platform`.
- CI передаёт в задание `l4` штатный `GITHUB_TOKEN` (только чтение) через
  `sudo --preserve-env=XM_GITHUB_TOKEN`, не аргументом.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Файл `/etc/xm/github-token` (`0600`) | токен постоянно лежит на диске VPS; новый путь в манифесте и `uninstall`; в CI всё равно приходит из окружения |
| Флаг `--github-token` | значение видно в списке процессов |
| Тег из перенаправления `releases/latest`, суммы только из `.dgst` | ослабляет проверку ADR-0009: вторая сумма — с того же узла, что и архив |
| Повтор до `X-RateLimit-Reset` | ожидание до часа; задание CI ограничено 15 минутами |
| Заглушка API в `l4.sh` | L4 перестаёт проверять настоящий источник |

## Последствия

- В [secrets.md](../security/secrets.md) §2 запрет переменной окружения относится к секретам,
  которые `xm` передаёт процессам; входной токен самого `xm` — названное исключение.
- Неверный или отозванный токен даёт отказ API (401) — запрос без токена не повторяется.
- Пересмотреть, если GitHub изменит лимиты или если `l4` снова упадёт на 403 при заданном
  токене.
