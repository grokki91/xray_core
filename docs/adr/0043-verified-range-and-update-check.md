# ADR-0043: проверенный диапазон версий Xray и итог проверки обновления

- Статус: Принято
- Дата: 2026-11-26

## Контекст

`updates.md` §2 требует ставить последнюю стабильную версию внутри проверенного диапазона,
хранить диапазон в `xm` данными и показывать доступную версию в `xm status`. Не было решено: в
каком виде задан диапазон, как найти релиз внутри него, если `/releases/latest` новее, откуда
`status` знает о новой версии и ставит ли `install` ту же версию. Выбор владельца — 2026-11-26.

## Решение

- Диапазон — две границы N.N.N включительно, `update.Verified()`; версии между границами
  считаются проверенными. Расширяется выпуском `xm`.
- Выбор — `update.Choose`: `/releases/latest`; в диапазоне — он; новее верхней границы — релиз
  верхней границы по тегу (`/releases/tags/v<max>`, тот же узел API); старше нижней — ошибка
  `ErrBelowRange`. `--to` запрашивает релиз по тегу тем же путём и ставит любую стабильную
  версию с пометкой `in_range: false`.
- `xm install` выбирает версию тем же `Choose`: правило одно.
- Итог проверки без `--to` (`target`, `latest`, время) записывается в
  `/var/lib/xm/cache/update-check.json`; `xm status` читает его без сети и показывает
  `update.version` (новее активной) и `update.checked`.
- `core.hold` — `xm update` ничего не меняет, в том числе с `--to`; `--check` работает.
- Новая версия проверяет действующую конфигурацию (`xray run -test`) до транзакции: провал не
  трогает службу. Каталоги версий, кроме активной и предыдущей, удаляются после успешного
  контроля — в том числе новее целевой после понижения через `--to`.
- Выбор, загрузка, проверка, транзакция и удаление версий — под одной блокировкой.
- Испорченный `update-check.json` — отказ `xm status` с подсказкой `xm update --check`: файл
  проверяется, потому что печатается человеку; поле ошибки в схеме не заводится.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Явный список версий | каждую версию вносить выпуском; выбор владельца — границы |
| Список релизов `/releases` с разбором страниц | больше кода и расход лимита API |
| Запрос к API при каждом `xm status` | `status` медленнее, зависит от сети и тратит лимит |
| `install` ставит `/releases/latest` | два правила выбора версии; установка вне диапазона без предупреждения |

## Последствия

- Версия между границами, на которой не прогонялись тесты, считается проверенной: цена выбора
  границ вместо списка.
- `xm status` показывает доступную версию на момент последней `xm update [--check]`; без
  проверки поле пусто.
