# ADR-0004: Одно состояние; конфигурация Xray — производная

- Статус: Принято
- Дата: 2026-11-13

## Контекст

Конфигурацию Xray можно править напрямую, но тогда она становится единственным местом, где
смешаны решения владельца, секреты и детали формата upstream, который меняется между версиями.

## Решение

- Источник правды — один файл `/etc/xm/state.json` (root, `0600`) с версией схемы и миграциями.
- Конфигурация Xray получается из состояния детерминированной функцией `config.Render` и руками
  не правится. Ручная правка считается дрейфом: показывается в `xm status`, сохраняется в снимок
  и перезаписывается при следующем применении.
- Секреты хранятся в том же файле состояния: один файл — одна атомарная запись.
- Формат — JSON, разбираемый стандартной библиотекой.

Структура и права — [data-model.md](../architecture/data-model.md).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Править `config.json` Xray на месте | нет модели, которую можно проверить и мигрировать; каждое изменение — разбор чужого формата |
| Отдельный файл секретов | две записи нельзя сделать атомарно; рассогласование хуже, чем общий режим `0600` |
| SQLite | зависимость и инструменты ради десятков записей |
| systemd credentials для конфигурации | недоступно на systemd 245; дало бы второй путь поставки конфигурации |

## Последствия

- Смена формата upstream затрагивает только `config.Render` и пресеты.
- Опытный пользователь не может настроить Xray руками в обход `xm` — это осознанное ограничение
  ради воспроизводимости; расширение возможностей идёт через пресеты.
- Все читатели состояния работают от root; непривилегированного чтения нет.
