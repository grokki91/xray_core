# Политика документации

## 1. Что где лежит

| Документ | Для кого | Содержит | Не содержит |
|---|---|---|---|
| `README.md` | пользователь | назначение, возможности, стек, структура, требования, одна команда установки, основные команды, кратко о диагностике | подробности, обоснования, историю |
| `docs/architecture/` | разработчик, LLM | как устроено сейчас | почему так (это ADR), планы |
| `docs/adr/` | разработчик, LLM | решение, альтернативы, последствия | описание реализации |
| `docs/security/`, `docs/testing.md`, `docs/dev/` | разработчик, LLM | политики: что обязательно | пересказ кода |
| `docs/operations/` | владелец, разработчик | как работают обновление и диагностика | данные конкретной установки |
| `docs/compatibility.md` | все | датированные факты о внешнем мире | вечные правила |
| `docs/roadmap.md` | все | фазы, состояние, критерии | архитектурные обоснования |
| `docs/open-questions.md` | владелец | решения, которые ждут его выбора | решённое (переносится в ADR) |

Пользовательские руководства (установка по шагам, туннель к панели, клиенты) появляются
отдельным каталогом `guide` внутри `docs/` вместе с соответствующей функцией.

## 2. Правила

1. **README короткий**: до 90 строк; всё остальное — ссылкой в `docs/`.
2. **Один факт — одно место.** Версии, пороги, совместимость — только `compatibility.md`;
   состояние работ — только `roadmap.md`; права и пути — только `data-model.md`; команды —
   только `interfaces.md`.
3. **Документ меняется вместе с кодом.** Правка, после которой документ говорит неправду, не
   закончена. Что обновлять — таблица §3.
4. **ADR не переписывается.** Принятое решение меняется новым ADR, старому ставится статус
   «Заменено ADR-NNNN».
5. **Датированное — с датой, источником и способом проверки.** Непроверенное называется
   непроверенным.
6. **Только фиктивные данные** в примерах ([secrets.md](../security/secrets.md) §4).
7. **Язык**: русский; идентификаторы, команды, имена файлов — как в коде. Термины — по
   указателю [docs/README.md](../README.md).
8. **Форма**: таблица вместо перечисления свойств; схема — Mermaid в самом документе; документ
   длиннее 100 строк начинается с содержания или обзорной таблицы; ссылки — относительные.
9. **Не обещать лишнего**: формулировки про обход DPI и блокировок запрещены; о диагностике
   говорится, что она измеряет, а не «определяет блокировку».

## 3. Что обновлять при изменении

| Изменилось | Обновить в той же правке |
|---|---|
| команда, флаг, код выхода | `interfaces.md` §1; README, если команда основная |
| поле машинного вывода | `interfaces.md` §2, эталон схемы |
| путь, владелец, права на VPS | `data-model.md` §1 |
| новый пакет или граница | `repository.md`, `components.md`, ADR |
| проверка диагностики | `diagnostics.md` §4 |
| версия, порог, совместимость клиента | `compatibility.md` |
| зависимость, инструмент | `dependencies.md` |
| завершение задачи или фазы | `roadmap.md` §1 |
| решён открытый вопрос | ADR; строка удаляется из `open-questions.md` |
| правило стало неверным | соответствующий файл `.claude/` или `AGENTS.md` |

## 4. Проверки

`scripts/check.sh` проверяет: относительные ссылки ведут на существующие файлы; пути в
инструкциях существуют; пределы размера; у каждого ADR есть статус; чувствительных данных нет.
Противоречия между документами ищет субагент `architecture-reviewer` при изменении архитектуры.
