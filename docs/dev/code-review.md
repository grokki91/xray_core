# Политика ревью

## 1. Кто и когда

| Шаг | Кто | Обязателен |
|---|---|---|
| Самопроверка | автор (агент): `bash scripts/check.sh`, чек-лист §2 | всегда |
| Ревью безопасности | субагент `security-reviewer` | изменение затрагивает пути правил `secrets.md`, `update.md`, `platform.md`, `interfaces.md`, юнит, права, хуки, CI |
| Ревью архитектуры | субагент `architecture-reviewer` | новый пакет, новый импорт между слоями, изменение `docs/architecture/` или ADR |
| Решение о слиянии | владелец | всегда |

Автор не сливает собственный PR и не одобряет его от имени владельца.

## 2. Что проверяется — по убыванию важности

1. **Эффект.** Изменение делает то, что заявлено; есть тест, который без него падает
   ([testing.md](../testing.md) §1). Непроверяемое тестом названо и снабжено ручной проверкой.
2. **Безопасность и секреты.** Нет нарушений [policy.md](../security/policy.md) §9; данные
   наружу идут через редактор; ввод проверяется до использования; фикстуры фиктивные.
3. **Границы.** Импорты по таблице [repository.md](../architecture/repository.md) §3; побочные
   эффекты только в `platform`; изменение системы только в транзакции.
4. **Один путь.** Нет запасных веток, деградированных режимов, «на всякий случай» —
   если они не запрошены и не записаны в ADR.
5. **Объём.** Правка равна задаче: нет попутного рефакторинга, незапрошенных возможностей,
   настроек «на будущее». Сложность, которую можно убрать, названа.
6. **Контракт.** Машинный вывод меняется по правилам версий; эталоны обновлены осознанно.
7. **Документы и инструкции.** Обновлены по таблице [documentation.md](documentation.md) §3.
8. **Зависимости.** Новых нет, либо есть согласие владельца и строка в реестре.
9. **Читаемость.** Имена, размер функций, комментарии «зачем», а не «что».

## 3. Замечания

| Уровень | Смысл | Что с ним делать |
|---|---|---|
| `blocker` | нарушение политики безопасности, потеря данных или доступа, сломанный эффект | исправить до слияния |
| `major` | нарушение границ, отсутствие доказывающего теста, незапрошенная сложность | исправить или получить явное согласие владельца |
| `minor` | читаемость, именование, мелкая неточность документа | исправить, если дёшево; иначе записать |

Форма замечания: `уровень · файл:строка · что не так · чем опасно · что сделать`. Замечание без
конкретного места и последствия не пишется. Похвала и пересказ изменения — тоже.

## 4. Критерии слияния

- `scripts/check.sh` и тесты уровня, требуемого изменением, зелёные на текущем коммите;
- нет открытых `blocker` и `major`;
- описание PR заполнено по шаблону, непроверенное названо;
- для изменений установки, обновления, юнита и прав — пройден системный тест (L4) или владелец
  явно принял риск.
