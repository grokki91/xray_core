# Экосистема разработки с LLM

Как устроены инструкции для агентов, что когда загружается и как это менять. Решение —
[ADR-0014](../adr/0014-ai-ecosystem.md).

## 1. Принципы

1. **Один вход.** `AGENTS.md` — единственное, что читается всегда; `CLAUDE.md` только
   подключает его и добавляет особенности Claude Code.
2. **Одна ответственность.** Каждое правило, скил, субагент и хук отвечает на один вопрос.
3. **Один факт — одно место.** В остальных местах — ссылка. Копии расходятся молча.
4. **Загрузка по потребности.** Чем уже применимость инструкции, тем позже она попадает в контекст.
5. **Правило без проверки — пожелание.** Всё, что можно проверить автоматически, проверяет
   `scripts/check.sh` или хук.

## 2. Уровни загрузки

| Уровень | Что | Когда попадает в контекст | Предел размера |
|---|---|---|---|
| T0 | `AGENTS.md`, `CLAUDE.md` | всегда | 150 и 40 строк |
| T1 | `.claude/rules/*.md` | при чтении или правке файлов из их `paths` | 40 строк |
| T2 | `.claude/skills/*/SKILL.md` | по типу задачи (описание скила) | 150 строк; подробности — в `references/` |
| T3 | `docs/` | по ссылке, разделами — через указатель [docs/README.md](../README.md) | — |
| T4 | субагенты `.claude/agents/*.md` | отдельный контекст; в основной возвращается только итог | 60 строк |

Пределы проверяет `scripts/check.sh`.

## 3. Состав

### Правила (T1)

| Файл | Область (`paths`) | Отвечает за |
|---|---|---|
| `agent-instructions.md` | `AGENTS.md`, `CLAUDE.md`, `.claude/**` | как править сами инструкции |
| `docs.md` | `README.md`, `SECURITY.md`, `docs/**`, `.github/**/*.md` | документация и ADR |
| `go.md` | `**/*.go` | общие правила кода и границы модулей |
| `platform.md` | `internal/platform/**` | побочные эффекты, запуск процессов |
| `config.md` | `internal/config/**` | отрисовка конфигурации Xray |
| `secrets.md` | `internal/store/**`, `internal/security/**`, `internal/redact/**`, `internal/backup/**`, `internal/logging/**` | обращение с секретами в коде |
| `update.md` | `internal/update/**`, `internal/core/**`, `install.sh` | загрузка и проверка бинарников |
| `diag.md` | `internal/diag/**`, `internal/monitor/**` | классы выводов диагностики |
| `interfaces.md` | `internal/cli/**`, `internal/api/**`, `internal/webui/**`, `internal/bridge/**`, `internal/contract/**`, `web/**` | адаптеры, контракт, панель |
| `tests.md` | `**/*_test.go`, `tests/**` | что считается тестом |
| `shell.md` | `install.sh`, `scripts/**`, `.claude/hooks/**` | скрипты на Bash |

Общие правила — в `AGENTS.md`; правила компонентов — здесь, по путям. Правило — короткая
выжимка «что делать при правке этих файлов» со ссылкой на политику в `docs/`, а не её копия.

### Скилы (T2)

| Скил | Когда загружается | Что даёт |
|---|---|---|
| `change` | любая задача, меняющая код или поведение | сквозной порядок: бриф → чтение → тест → правка → документы → проверка → PR |
| `adr` | решение меняет границы, контракт, данные, безопасность или зависимости | когда нужен ADR и как его писать |
| `xray-upstream` | задача опирается на поведение, версии или конфигурацию Xray | где правда об upstream, как её проверить и записать |
| `client-profiles` | профили, ссылки, QR, форматы клиентов | формат артефактов и порядок добавления экспортёра |
| `diagnostics` | проверки, выводы, отчёты | модель наблюдений и порядок добавления проверки |

Появятся вместе с потребностью, не раньше: `release` (фаза 1), `preset` (первый второй пресет),
`system-test` (фаза 4).

### Субагенты (T4)

| Субагент | Задача | Инструменты | Возвращает |
|---|---|---|---|
| `security-reviewer` | проверить изменение по политикам безопасности и секретов | только чтение | список замечаний по форме |
| `architecture-reviewer` | проверить границы модулей и соответствие ADR | только чтение | список нарушений по форме |
| `upstream-researcher` | установить факт об Xray или клиенте по первичным источникам | чтение, клонирование во временный каталог | факт, дата, источник, способ проверки |

Субагент нужен там, где работа требует много чтения, а основному контексту нужен короткий
итог: ревью большого изменения, чтение чужих исходников.

### Хуки и автоматические проверки

| Момент | Механизм | Что делает |
|---|---|---|
| Запись файла | хук `write-guard.sh` (PreToolUse: Write, Edit) | отказ при секрете в тексте и при запретном имени файла |
| После правки | хук `change-notes.sh` (PostToolUse: Write, Edit) | один раз за сессию напоминает политику по классу файла: архитектура, конфигурация, зависимости, чувствительный модуль, инструкции |
| Перед коммитом и отправкой | хук `publish-guard.sh` (PreToolUse: Bash) | `git commit`, `git push` — только при зелёном `scripts/check.sh`; текст команды проверяется на секреты |
| Перед созданием и правкой PR, комментарием | хук `publish-guard.sh` (PreToolUse: инструменты GitHub) | то же для текста PR и комментариев |
| Изменение архитектуры | `change-notes.sh` + `scripts/check.sh` | напоминание об ADR; новый пакет `internal/` без строки в `repository.md` — провал |
| Изменение конфигураций | `change-notes.sh` + правило `config.md` | эталон, `xray run -test`, фиктивные данные |
| Добавление зависимости | `change-notes.sh` + `scripts/check.sh` | изменение `go.mod`, `go.sum`, `.github/workflows/`, `web/vendor/` без правки реестра — провал |
| Чувствительные данные | `scripts/guard.sh`, запреты чтения в `.claude/settings.json` | сканер; `.env`, `*.pem`, `*.key` не читаются |

`scripts/check.sh` — единая точка обязательных проверок: её вызывают хуки, агент перед
завершением задачи и, после согласия владельца, CI. Хуки — удобство Claude Code; гарантию для
любых инструментов и людей даёт CI ([tooling.md](tooling.md)).

## 4. Экономия контекста и токенов

- **Неизменяемый префикс.** `AGENTS.md` и `CLAUDE.md` не содержат дат, состояния фаз и версий:
  всё изменчивое живёт в [roadmap.md](../roadmap.md) §1 и [compatibility.md](../compatibility.md).
  Префикс, который не меняется между сессиями, кешируется платформой; правка `AGENTS.md`
  сбрасывает кеш у всех, поэтому она редкая и осознанная. При работе через API статические
  инструкции ставятся в начало запроса, точка кеширования — сразу после них.
- **Чтение разделами.** Документы длиннее 100 строк начинаются с содержания или таблицы;
  агент читает нужный раздел, а не файл.
- **Тяжёлое чтение — в субагенте.** Чужие исходники и большие диффы не попадают в основной контекст.
- **Формы вместо прозы.** Вход — бриф, выход — отчёт фиксированной формы (`AGENTS.md`),
  результат субагента — список по шаблону из его описания.
- **Без дублей.** Правило ссылается на политику, скил — на документ; пересказ запрещён
  правилом `agent-instructions.md`.
- **Язык.** Инструкции и документы — на русском: их читает и правит владелец, так же устроены
  соседние репозитории. Цена — больше токенов на тот же объём текста, чем на английском; пределы
  размера её ограничивают (вопрос Q11).

## 5. Переносимость

`AGENTS.md` читают разные инструменты. Всё обязательное для любого агента — в нём и в `docs/`.
Каталог `.claude/` — реализация для Claude Code: правила по путям перечислены в таблице §3,
чтобы агент без автоматической подгрузки открыл нужное сам; скилы и описания субагентов — обычные
Markdown-файлы, пригодные как инструкции где угодно.

## 6. Как менять экосистему

Правило `.claude/rules/agent-instructions.md`. Коротко: инструкция меняется в той же правке,
что и код, после которой она стала неверной; новый элемент добавляется, когда есть повторяющаяся
потребность, и получает строку в таблицах §3.
