# План реализации

Фазы идут по порядку; следующая не начинается, пока не выполнены критерии предыдущей. Одна
сессия LLM берёт одну задачу фазы по [брифу](templates/task-brief.md). Изменчивое состояние
проекта хранится только здесь, в таблице §1.

## 2. Фазы

### Фаза 0 — Архитектурный фундамент

- **Цель**: согласованная архитектура и экосистема разработки, которую можно передать любой
  сессии LLM без устных пояснений.
- **Задачи**: документы `docs/`; ADR; инструкции, правила, скилы, субагенты, хуки; проверки
  репозитория; ответы владельца на [открытые вопросы](open-questions.md).
- **Зависимости**: нет.
- **Критерии завершения**: PR принят; вопросы Q1–Q5 решены и перенесены в ADR; согласован
  список инструментов из [tooling.md](dev/tooling.md).
- **Проверки качества**: `bash scripts/check.sh`; документы не противоречат друг другу (ревью
  субагентом `architecture-reviewer`).
- **Результат**: этот набор документов.

### Фаза 1 — Каркас

- **Цель**: собирающийся бинарник с границами модулей и конвейером выпуска — до любой
  прикладной логики.
- **Задачи**: модуль Go и раскладка каталогов; `platform` (настоящая и поддельная
  реализации); `store`; `redact`; `contract`; диспетчер CLI с `version` и `help`; тест графа
  импортов; канареечный тест редактора; сборка и выпуск `xm` с `SHA256SUMS`; `install.sh`,
  который ставит `xm`; CI (после согласия). Спайки: стенд сквозного теста с настоящим Xray;
  системный тест на размещённом исполнителе; наличие хэша файла релиза в API GitHub.
- **Зависимости**: фаза 0; согласие на CI и инструменты проверки.
- **Критерии завершения**: `install.sh` на чистой Ubuntu ставит `xm`, `xm version` отвечает;
  тест границ падает при запрещённом импорте; спайки дали ответ «работает / не работает» с
  записью в ADR.
- **Проверки качества**: L0–L2; размер бинарника в бюджете; ревью `security-reviewer`
  (загрузчик, выпуск).
- **Результат**: выпуск 0.0.x — пустой, но проверяемый и устанавливаемый каркас.

### Фаза 2 — Ядро и служба

- **Цель**: `xm` ставит проверенный Xray и управляет службой с рабочей конфигурацией.
- **Задачи**: `update.Source` (загрузка и проверка сумм); `core`; `security` (пользователь,
  манифест прав, ключи); `config` с одним пресетом (вопрос Q1); `logging`; `server`
  (предусловия, юнит с изоляцией, служба); каркас транзакции в `app` со снимком; команды
  `start`, `stop`, `restart`, `status`.
- **Зависимости**: фаза 1; решения Q1, Q3.
- **Критерии завершения**: на чистой машине служба Xray запущена от пользователя `xray` с
  конфигурацией из состояния; провал на любом шаге транзакции возвращает исходное состояние;
  испорченный архив отвергается до установки.
- **Проверки качества**: L1–L4; `xray run -test` на эталонах; манифест прав; замер памяти Xray
  на целевой конфигурации VPS.
- **Результат**: управляемая служба без профилей.

### Фаза 3 — Профили

- **Цель**: профили и клиентские артефакты из одного места.
- **Задачи**: `profile` (создание, список, показ, удаление); экспортёры `uri` и `qr`; таблица
  совместимости данными и её сверка с [compatibility.md](compatibility.md); команды `add`,
  `list`, `show`, `rm`; сквозной тест «экспортированный профиль → клиент Xray → петля»;
  решение по зависимости для QR.
- **Зависимости**: фаза 2.
- **Критерии завершения**: ссылка из `xm add` принимается клиентом Xray в сквозном тесте;
  ссылка для IPv6 корректна; удалённый профиль перестаёт подключаться; экспорт под
  несовместимый клиент — ошибка с причиной.
- **Проверки качества**: L1–L3; тест «ссылка → разбор → те же параметры»; канареечный тест на
  командах профилей.
- **Результат**: сервер, к которому можно подключиться.

### Фаза 4 — Установка целиком

- **Цель**: основной сценарий — одна команда на чистом VPS до ссылки и QR.
- **Задачи**: `network` (адреса IPv4 и IPv6, порт, внешний адрес, проверка цели REALITY);
  `dns` (DoH, стратегия семейств адресов); сценарий `install` с идемпотентностью и обнаружением
  чужой установки; `uninstall`; системные тесты на Ubuntu 22.04 и 24.04.
- **Зависимости**: фазы 2, 3.
- **Критерии завершения**: `install.sh` на чистой Ubuntu 22.04 и 24.04 заканчивается ссылкой и
  QR без вопросов; повторный запуск ничего не меняет; `uninstall --purge` не оставляет следов
  по манифесту; сервер с одним только IPv4 и сервер с IPv4 и IPv6 дают корректные профили.
- **Проверки качества**: L4 на двух ОС; тест идемпотентности; ручная проверка на живом VPS (L5).
- **Результат**: рабочая установка.

### Фаза 5 — Надёжность

- **Цель**: систему можно обновлять, восстанавливать и проверять.
- **Задачи**: `update` с проверенным диапазоном, контролем и откатом, `--rollback`, `--self`;
  `backup` (команды, хранение, проверка) и `restore`; `diag` с минимальным набором проверок
  (пометка MVP в [diagnostics.md](operations/diagnostics.md) §4) и отредактированным экспортом;
  `logs`; короткий README и пользовательская документация.
- **Зависимости**: фаза 4.
- **Критерии завершения**: критерии MVP (§3).
- **Проверки качества**: L1–L5; обновление и откат между двумя версиями Xray в системном тесте;
  канареечный тест на экспорте диагностики.
- **Результат**: **MVP — выпуск 0.1.0**.

### Фаза 6 — Диагностика и мониторинг

- **Цель**: полный Diagnostics Engine и хронология.
- **Задачи**: все категории каталога; правила анализа и классы выводов; история и сравнение
  отчётов; `monitor` с systemd-таймером и счётчиками трафика; `xm monitor on|off`; формат
  наблюдений, пригодный для внешних точек.
- **Зависимости**: фаза 5.
- **Критерии завершения**: у каждой проверки тесты на `ok`, `fail`, `skip`; ни один сценарий не
  даёт выводу о фильтрации класс `fact`; прогон укладывается в бюджет времени и соединений;
  мониторинг держит объём хранения в пределе.
- **Проверки качества**: L1–L4; тесты правил классов; замер нагрузки мониторинга.
- **Результат**: выпуск 0.2.0.

### Фаза 7 — API и Web UI

- **Цель**: минималистичный интерфейс через SSH-туннель.
- **Задачи**: `api` (сессия, эндпоинты [interfaces.md](architecture/interfaces.md) §3);
  `webui` и `web/`; команда `ui`; QR в SVG; документация по туннелю.
- **Зависимости**: фазы 5, 6; решение Q6.
- **Критерии завершения**: все возможности из §4 интерфейсов работают через туннель; панель не
  слушает публичные адреса; запросы без сессии, с чужим `Host` и `Origin` отвергаются; процесс
  завершается сам; память в бюджете.
- **Проверки качества**: тесты API; системный тест «через тоннель VPN панель недостижима»;
  ревью `security-reviewer`.
- **Результат**: выпуск 0.3.0.

### Фаза 8 — Усиление и выпуск 1.0

- **Цель**: закрыть оставшиеся требования безопасности и совместимости.
- **Задачи**: аудит (`security.Audit`) и `xm harden` с защитой от потери доступа (Q7);
  совместимость с Ubuntu 26.04; решение по 20.04 (Q8); пересмотр модели угроз; проверка
  бюджетов; полная документация; чек-лист приёмки.
- **Зависимости**: фазы 5–7.
- **Критерии завершения**: требования политики безопасности §2 закрыты и проверяются тестами;
  приёмка L5 пройдена на 22.04 и 24.04; 26.04 — проверена или описаны расхождения.
- **Проверки качества**: полный прогон L0–L5; независимое ревью безопасности.
- **Результат**: выпуск 1.0.0.

### Фаза 9+ — Расширения

Каждое — отдельный ADR и план; порядок выбирает владелец.

| Расширение | Предварительное условие |
|---|---|
| Мост для `xray_client` | анализ его контрактов, ADR (Q4) |
| Внешние диагностические узлы и сравнение точек | формат наблюдений из фазы 6 |
| Несколько VPS | контракт `--json` стабилен; реестр узлов в `server` |
| Новые пресеты (Vision, другие протоколы upstream) | каталог пресетов, таблица совместимости |
| Автообновление по расписанию | статистика откатов из фазы 5 (Q9) |
| Автоматизированный анализ накопленной диагностики | история из фазы 6 |
| Выгрузка снимков за пределы VPS с шифрованием | отдельный ADR |

## 3. Критерии готовности MVP

MVP — минимальная версия, которую можно установить и использовать без Web UI.

Функции:

1. Одна команда из README на чистой Ubuntu 22.04 или 24.04 (x86_64) завершается ссылкой VLESS и
   QR-кодом без вопросов.
2. Повторный запуск установки ничего не ломает и не перевыпускает ключи.
3. Работают команды: `install`, `uninstall`, `start`, `stop`, `restart`, `status`, `add`,
   `list`, `show`, `rm`, `update`, `diag`, `logs`, `backup`, `restore`, `version`, `help`.
4. Профиль подключается клиентами v2rayN и Hiddify 5.x — проверено на устройствах (L5).
5. IPv4 и IPv6: сервер слушает оба семейства, профиль выдаётся для каждого адреса.
6. `xm update` обновляет Xray с проверкой сумм и откатывается при провале контроля.
7. `xm diag` выполняет минимальный набор проверок и экспортирует отредактированный отчёт.

Качество:

8. Тесты L0–L4 зелёные на 22.04 и 24.04; канареечный тест не находит секретов в выводе.
9. Xray работает от непривилегированного пользователя; права совпадают с манифестом.
10. В репозитории, выпуске и журналах нет секретов и данных установки.
11. Бюджеты памяти и размера выполнены.
12. README умещается в один экран команд; подробности — в `docs/`.

Вне MVP: Web UI и API, мониторинг, полная диагностика, `harden`, мост, несколько VPS.
